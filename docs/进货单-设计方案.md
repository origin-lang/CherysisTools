# 手机「进货单」（补货单）— 设计方案

> 2026-10-15 立项。**手机端为主**，电脑端不做（后端 handler 是共用的，电脑端以后想接随时能接）。
> 讨论记录见 `.workbuddy/memory/2026-10-15.md`。

## 一、要解决的事

早上给别人发货的时候，会发现有些商品要补货。**他要带着单子去档口拿货**，得让去拿货的人知道
"哪个编号、补多少"。现在靠**截图 + 一个个说数量**，麻烦且容易漏。

所以这件事的本质是：**把"要补什么"记成一张单，然后一键复制成文字发出去。**

## 二、一句话流程

发货 → 发现缺货 → 掏出手机输编号（自动出图）→ 填要补多少 → 攒成今天这张单 →
点「复制清单」发微信给去档口的人 → 拿回来填"实拿多少"、写备注。

## 三、位置：底部第三个 tab「进货」

底部从「商品 / 设置」变成「**商品 / 进货 / 设置**」（**B 方案**）。

- ⚠️ 底部 `.tb` 原来写死 116px，三格会顶到右侧连接灯 → 得改成能容三格（见实施清单）。
- ❌ **不做**"在商品列表/详情上加『加入进货单』"这个快捷入口（老板说暂时不加，以后再说）。

## 四、字段口径（老板定的）

| 在哪 | 字段 | 说明 |
|---|---|---|
| 整张单 | **日期** | **一个**整单日期，**带年份**（`2026-10-15`）；默认今天，可改 |
| 整张单 | 备注 | 整单备注 |
| 整张单 | 状态 | **自动算出来，不手填**（见第五节） |
| 一行 | 编号 | 手输，自动带出名称/图片（**输纯数字会自动补成 `A` + 3 位**，见五 B） |
| 一行 | 需求数 | **要补多少**（不是"库存补到多少"） |
| 一行 | 实拿数 | 实际拿到多少 |
| 一行 | 备注 | 行备注，如"档口只剩 6 条" |

- ❌ **不碰库存**：老板明确说现在库存统计不准、现实很乱，"库存这一块暂时不好做"。
  所以录入界面**不显示库存**、也**不根据库存推荐补多少**。
- ❌ **不做**「照昨天的单再来一张」。
- ❌ **不做**「谁去拿」字段（以后作为扩展需求再说）。
- ❌ **不做**发货流水（发货只是"发现缺货"的场景，不是要记的账）。

## 五、状态怎么显示（我的建议，已实现）

**整单状态由行自动汇总，不让人手填** —— 手填状态一定会跟数量打架
（填了实拿=需求，状态还写着"未完成"，界面就在说谎）。

- **一行"办完没办完"＝看数量，不看勾**：需要 20、拿到 20 → 这行算**齐**；
  `isReady(it)` = `need > 0 && got >= need`，是**唯一口径**（复制清单的 `✓`、整单状态都走它）。
- ⚠️ 2026-10-16 晚 **「已办」那个手工勾整个撤了**（老板："那个勾选那个好没有必要吧"）：
  填了"拿"其实就说明办了，再多一步点勾是多余动作。行上少一格（名称那一栏多出 26px），
  `done` 那列**库里还在、后端一行没动** —— 前端把它当**派生值**传（`done: isReady(...) ? 1 : 0`）。
- 整单状态（`calcSummary()`）：全拿齐 →「**已完成**」/ 一款没动 →「**未开始**」/
  中间 →「**已齐 2/5**」。**没有"进行中"这个词了**（那是按勾数的旧口径）。
- ⚠️ 2026-10-16 晚 **那三颗徽标（`+3` / `缺4` / `待拿` / `齐`）也整个撤了**
  —— 原话"代拿…很没有必要有点多余"。位置让给**行内小图**（见下）。判断"缺还是多"看**"拿"那一格的染色**：
  多拿染绿、缺染橙、正好染绿（老板要的"多拿了一眼看出来"）。`itemBadge()` 连同它的断言一起删了。
  ⭐ 当晚又**只补回了"差额数字"这一个**（见五 B 的"行尾差额小字"）—— 不是把徽标整套搬回来。
- 单详情**列表底下压成一行汇总**：`共 3 款 · 需 30 · 拿 29 · 差 -1 · 已齐 1/3`（跟列表屏同一口径）。

## 五 B、界面（2026-10-16 改版，老板挑的档）

**首页（进货 tab 一进去）＝ 月历**（原来是一张单一张卡片）：

- 顶上 `‹ 2026 年 10 月 ›` 换月；**有单的日子带绿点**；点一下日子，下面出**当日卡**。
- 当日卡：这天有单 → 每张单一张卡（日期 + 状态 + 汇总 + 整单备注 + **打开填写** + 删除）；
  这天没单 → 「**新建这天的单**」，日期就落那天（不是今天）。
- 翻到别的月会出现「回到本月」。顶栏「＋ 新建」仍是开今天的单。
- ⚠️ **全部单击，不用双击** —— 手机上双击跟缩放手势打架、换个人用也想不到。
- 保存/删除后后端本来就会推 `purchaseState`，绿点和当日卡**自动刷新**，不用额外拉。

**填表页＝ 带小图的行**（2026-10-16 晚，老板挑的 **B 档**；上一版是"紧凑行"）：

- 一行 = `[小图 44] [编号] [名称…] [需] [拿]`。**小图常驻在行上** ——
  老板原话"点击才看到图片真的好吗？我感觉是不是不直观"，所以图不再藏在展开块里。
- 代价写在明处：行高从约 40px 涨到约 **56px** → 一屏从 15 款降到 **11 款上下**（这是看图的代价）。
- 有编号才去取图（接口 `imgUrl(code,"","thumb")`，`loading="lazy"`）；**空行不去取图**，
  只出一格「编号」占位；取不到（404）由 `onerror` 抹掉 img、露出底下的「无图」——
  不留破图、也不留一片空。
- **需/拿还在行上直接输**（录入不变慢）；点行的空白处展开/收起：**全名、编号提示、备注、删行**
  （图不进展开块了，行上已经看得见 —— 不重复放），**一次只摊一行**（`state.openRow`）。
- 展开用**单击**（替代原来说的双击，理由同上）。
- 表头（编号/名称/需/拿）跟行是同一套 flex + 列宽，对得齐；表头里给小图留的那格（`.himg`）也是 44px。

### 行尾差额小字（2026-10-16 晚，老板挑的"丙档"）

老板："我填完了拿之后…就比如说加 6 什么显示一下，这样的话我也不用自己去算了。"

- **长什么样**：多拿 → `+6`（品牌绿）、缺 → `-4`（橙），11px，跟着名称右边、贴着名称栏的右端。
  颜色跟「拿」那一格的染色同一套（`.pi-got.over/under`），等于**把颜色变成数字**。
- ⚠️ **挂法**（这是三档里挑出来的关键）：它挂在**名称栏里面**（`.pit-name` 的子节点 `.pi-d`），
  **不是新开一列**。所以：
  - 名称栏总宽不变，代价只是**这一行**的名称早一点截断（约 1~2 个字 —— 老板："名称栏短一点没关系"）；
  - **没差额的行根本不渲染这个节点 → 名称仍是满宽**（新开一列的话那 26px 每行都白留）。
  - 当时摆的三档：甲＝跟在「拿」格右边另开一格（每行白窄 26px）、乙＝并进「拿」格（省一半宽度，
    但数字贴框边、只有两个字符位、三位数会撑开跟表头错位）、**丙＝挂在名称栏里（老板选的）**。
- **只在真有差额时出现**：需/拿**不相等**才显示。正好（差 0）不显示（那"拿"格本来就是绿的）。
- ⚠️ **拿 0 也显示 `-6`**（2026-10-17 下午改的，原来不显示）。老板原话："如果我需要 6 但是拿填了 0
  怎么不显示 -那个数 虽然也在缺货里面 但是不明显"。
  原来的理由是"还没去拿不算缺，每行挂个 `-10` 就是当年那颗「待拿」徽标"—— 但那样跟「缺货」筛选
  **自相矛盾**：列表把它筛出来了，行上却一个数都没有（等于"我告诉你它缺，但不告诉你缺几件"）。
  ⭐ **现在的规矩：能进"缺货"列表的行，行上就必须看得见差多少** —— `itemDiff()` 与 `isShort()` 同一口径。
  唯一还拦的是"需没填"（空行没有参照物，不拦会凭空冒个 `+5`）。
- 口径跟复制清单、汇总那行的"差"**必须一致**：同一个 `fmtNum` + 正数补 `+`。
  实现是 `itemDiff(it)`（返回 `null` / `{txt, over}`），纯函数、单测直接打它。
- 边打字边变：`updateRowLive()` 不只改文字，**没差额时还要把节点删掉**（不然名称栏白少一块）。

### 编号归一：输 `006` 自动补成 `A006`（2026-10-16 晚）

老板问："假如说我输 006，你给我自动补充为 A006。能做到吗？……如果觉得没必要就不做了。"

⭐ **结论：好做，而且该做 —— 它不是新功能，是手机端这一格当初漏了归一（界面在跟后端打架）。**

- **病在哪**：后端 `handlers/purchase.ts` 保存那张单时，编号走的是 `canonicalCode()`
  —— 也就是说**输 `006` 存进库里的本来就是 `A006`**。而手机端那一格当初只做了"去空格 + 转大写"，
  于是输 `006` 的那一刻：名称栏写「无此编号」、行内小图也取不到
  （图是按编号存成**文件夹**的，`A006/` 有、`006/` 没有）→ 「无图」；**可返回重进这张单，它又全对了**。
  ＝界面说的和库里存的是两回事。这才是他觉得"应该自动补 A"的真实原因。
- **真库实测**（`shop.db` 527 条）：**全部是"字母 + 3 位数字"，无一例外**；
  前缀 A 520 / T 5（套装）/ B 1 / L 1 → "纯数字算 A 段"在 98.7% 的情况下就是对的。
- **口径出处只有一个**：`src/tools/shopTool/pricing.ts` 的 `canonicalCode()`
  —— 后端保存、桌面端直播排品输编号、**手机版商品筛选的区间语法**（`1~33` 当 A1~A33）用的都是它。
  手机端 `purchase.js` 抄了一份（守「独立功能文件」约定，不往 app.js 塞），
  ⚠️ **改一处必须四处同改**；自检里有一条**拿后端编译产物逐例比对**的断言钉着防漂。

| 你敲的 | 归一成 |
|---|---|
| `6` / `06` / `006` | `A006`（补零到 3 位） |
| `a6` / `A6` | `A006` |
| `T5` | `T005`（自带字母的前缀留着） |
| `A1044` | `A1044`（1~4 位；字母后 4 位照认，`A0001` → `A001`） |
| `000` / `0` / `XD` / 空 | 归一不了 → **保留原文照样记**（老板拍的口径："归一不了的就记，只不过说没有这个编号罢了"） |

- ⚠️⚠️ **必须失焦才回填，绝不能边打字边补**：`canonicalCode` 对**没输完的内容照样补零** ——
  想敲 336、敲下第一个 `3` 的瞬间它得到的就是 `A003`。桌面端直播排品早踩过这个坑
  （规矩写在 `client-live.js:224`）。实现就放在**原有的 change（失焦/回车）那一步**，
  自检里有一条静态断言**禁止它出现在 oninput 里**（改坏会立刻变红）。
- 归一之后输入框**当场回填成规范形式**（所见即所存），名称和图立刻出来。
- 已知代价：**纯数字默认前缀 A** —— 想录 T/B/L 开头的得自己敲那个字母
  （⚠️ 后端/桌面端现在也是这个坑，不是这次新引入的）。

### 款数口径 ＝「真正几款货」（有编号的行数）— 2026-10-16 晚

老板："（并进去）这样的话就一定是到时候共有多少个款对不对？"

- **款数 ＝ 有编号的行数**（不是 `items.length`）：点了「＋」还没输编号的那一行**不是一款货**。
  原来把空行也算进去 —— 屏幕上说 4 款、导出的表格里说 3 款（Excel 那边 `normExportItems` 早就滤了空行）。
- ⚠️ **不去重**：重复编号**根本到不了这一步**（编号一定稿就自动并进已有那行，见下一条）。
  真去重反而会算出「共 2 款 · 需 36」这种自相矛盾的数（款数去了重、数量还是两行相加）。
- 与后端 Excel 汇总行那句「共 N 款」**同一口径**（都按有编号的行数、都不去重）——
  这次只是把两边对齐确认了一遍，**后端不用改**。

### 重复编号：提示 + 自动并进已有那行 — 2026-10-16 晚

老板："首先你得有提示，然后自动编进去。"

- 一行的编号**定稿**（失焦/回车）后，发现这单里**别的行**已有同一编号 → **并进那一行**：
  需相加、拿相加；备注**以已有那行为准**，新行写了就拼在后面（`；` 连接）—— 别丢他刚打的那句话。
- **提示**（他要的"得有提示"）：toast **就一句话**「已经有过了，已并进那一行」
  —— 老板 10-16："你就写已经…已经有过，已并进那一行就可以了，不用再说其他的了"，
  所以**不再报编号、也不再报"需 20 → 26"**（那一行本来就在高亮，位置和数字他自己看得见）。
  目标行**持续高亮**（见下一条）。
- 撞车那一行**被删掉**（`splice` + 删掉它的 DOM 节点 + 后面那些节点的行号往前挪一格）。
- ⚠️⚠️ **不重建 DOM**：change（失焦）**早于**他点的那一下，重建会让他点空
  （手机上表现为"点了一下没反应、得再点一次"）。靠 `appendChild` 把节点从原位置摘走重挂 —— **只挪节点、不重建**。
- 为什么不是"只提示不合并"：一趟趟手动合并太累，而且款数会一直在说谎。

### 编号自动排序（只在编号定稿时）— 2026-10-16 晚

老板："你每次添加一个你就排序有序不就保证了吗？"

- 编号定稿后按 `codeKey` 升序排：**字母 → 数字**。
  ⚠️ 数字按**数值**比，不能按字面 —— 否则 `A1044` 会排到 `A999` 前面。
  没编号、或归一不了的（`XD`）一律**留最后**，彼此保持原有先后（靠 `Array#sort` 的稳定性）。
- ⚠️ **只在编号定稿时排**：他填「拿」的时候**绝不重排** —— 档口现场刚填完一行就换位置，手就找不着刚才那行了。
- **展开的行**（`openRow`）跟着**它自己**走（不是跟着下标），否则展开块会串到别的商品上。
- **位置真变了才高亮**（顺着编号往下加时顺序本来就不变，那种情况亮就是纯噪音）。
- 同上：**只挪节点、不重建**（`reorderRows`），他正在输的那个输入框还是同一个元素，焦点/键盘都不受影响。
- ⚠️⚠️ **回车必须显式接 `keydown`（这条 10-16 晚补的，是"排序没生效"的真因）**：
  裸 `<input type="text">`（不在 `<form>` 里）**按回车不触发 `change`**，只有"失焦"才触发 ——
  老板输完 `361` 直接按回车，归一 / 合并 / 排序**一个都没跑**，于是他报"你怎么没做编号排序、361 还在最底层"。
  做法：`commitOnEnter(e)` 在 keydown 里 `blur()` 一下 —— 浏览器自然把 `change` 补上来，
  后面那套（归一 → 撞车合并 → 自动排序）**原封不动复用，不会有第二条口径**。
  认 `Enter` / `Go` / `Done` / `Next` / `Search` + `keyCode 13`（各家软键盘叫法不一样）。
  手机端别处早就这么干了（`app.js` 的 `$("q").onkeydown`、`#setAddCode`），进货单当初漏了。
  ⚠️ **只能在 keydown 里做，绝不能挪去 `oninput`**（理由同上面编号归一那条）。

### 落位那一行 ⇒ 持续高亮（不是"闪一下"）— 2026-10-16 晚

老板："为什么你并起来你不能自动停的那一行给我有个颜色标一下…你先帮我高亮在哪里，
难道还要去眼睛找多麻烦呀。"

- **两个出口都要标同一行**：① 编号撞车**并进**哪一行；② 编号排序后那一行**挪到了**哪儿。
  两处都调 `markRow(item)`。
- ⚠️⚠️ **必须是"持续"高亮，不能是"闪一下"**：第一版做成 1.3 秒的 `.fresh` 动画，老板**根本没看见** ——
  手机软键盘挡着半屏、行本来就可能在他视线外，等他看清已经闪完了。
  → 现在 `.fresh` 只负责"落位那一下"的强调，**动画结束停在同一个淡绿上**（`pi-hit` 的 `to` 从 `var(--card)` 改成 `rgba(35,168,132,.12)`），
  再由 `.pit.hit` 这个**常驻 class** 把颜色留住。
- **什么时候撤**：他开始打字（`input` 监听开头 `clearHit()`）、或**另一行落位**（`markRow` 里先 `clearHit()`，同时只留一行）。
  不主动撤也不对 —— 满屏挂绿就是噪音。
- **左边那条竖线用 `inset box-shadow` 画，别用 `border-left`**：border 会把整行往右挤 3px、跟表头错位。
- **滚屏用 `block:"nearest"`**：已经在屏幕里的行**一点不滚**（不把他正看的地方拽走），
  只有被键盘挡住时补最小距离。老 WebView 没有 `scrollIntoView` 也要**不抛异常、高亮照样在**。
- ⚠️ **`.fresh` 在同一元素上不重播** → 摘 class → `void el.offsetWidth` 逼一次重排 → 再加回。

### 「＋ 加一行」⇒ 屏幕底部浮动条（A 档）— 2026-10-16 晚

老板："我列表太长的时候，我每次要滚到最上面找那个加号要补商品，是不是很麻烦呢？"

**问题属实**：那颗「＋」原来挂在卡片表头 `.p-head`（跟「要补的商品」同一行）里，
整块卡在**会滚的内容区**里 → 列表一长它就被顶出屏幕，每加一款货都得先滚回顶上。
⭐ 而且**刚做的自动排序会把新加的行插到列表中间** → 加完一行视线停在中间，离顶上那颗＋更远。

### 点行展开 ⇒ 只切 class，不重画列表（2026-10-17 修"其他商品跟着闪一下"）

老板："为啥我点进货单一个商品（准备看详情），其他商品跟着闪一下呢？不是全刷新吧，怕影响性能。"

**他猜对了，就是全刷新**：点行展开原来走整块 `renderItems()` —— 列表里**所有 `<img>` 都重建**、
重新请求 + 重新解码，所以整列闪一下；列表越长越明显，也确实白花性能。

**修法**（跟筛选面板 `toggleGroup()` 当年"只切 class、不重画"是同一课）：

- 展开块 `.pit-x` **每行都画**，CSS 默认 `display:none`；行带 `.open` 才 `display:block`。
- 点行 → `toggleOpenRow(i, box)`：**摘掉旧行的 `.open`、挂上新行的 `.open`**，两次 classList 操作完事，
  一个 `<img>` 都不动 —— 不闪、零请求，列表再长也是同样的开销。
- `state.openRow` 仍要维护（`mergeSameCode` / `sortDraftItems` / 删行都靠它），只是 DOM 不再跟着重建。
- 连带一致性都核对过：删行节点连着展开块一起删；排序挪节点时展开块跟着**它自己**走；换单全量重画时按
  `openRow` 恢复 `.open`。自检里钉了"同时只摊一行""openRow 要跟上""旧 openRow 指着不存在的行不许抛"。

### 现场新货行 ＋ 两段开关（「乙′」，2026-10-17）

老板："有新的商品能不能也通过进货单添加进去……我可能说这个编号还没有，那我怎么记这种临时的信息呢"、

**形态**：单子上一条两段开关「要补的 N / 现场进的 M」。**外观是两页、底层是同一张单** ——
按行的 `kind` 筛，不是两份清单。所以汇总、导出 Excel、复制清单一律是**一份**，
不用维护两套"合并"逻辑（这就是没选"真·两个 tab"的原因：真分开就得处处合并）。

**现场新货行**（kind=1）是**两行、一个框都不画**（2026-10-17 晚定稿，老板挑的 B 档）：

```
第一行   [认货照 44] [名称]        [进价 58] [件 44]
第二行   [备注（可空）………]  [¥114]  [🗑]
```

- 现场没有"本来该要几件"这回事，所以**没有「需」**；要那种就是补货行。
- ⚠️⚠️ **没有展开块**。原来那个抽屉里只剩"一行删除按钮 + 左边一大片空白"，而这一行四个格子
  全是 `<input>`/`<button>` —— 点行的空地才有几个像素，老板原话"**详情能点击的地方太小了
  不好打开，而且打开后只有一行删除按钮 然后左边一大片空白**"。去掉抽屉后：备注常驻、
  删除常驻，**点不开和留白两个问题一起消失**（也叫"现场行本来就没多少东西，不该有抽屉"）。
- ⚠️ **进价必须在行上**（老板："为什么现场进的没有填价格？进价多少钱我需要记下"）——
  原来只有抽屉里有，等于要展开才看得见。
- ⚠️ **合计在第二行右端，只写 `¥114`**：`进价 × 件数`。**不挂在名称下面** —— 老板：
  "合计写在名称下面 感觉可能一行显得很挤 或者说由于高度不够 看着很不美观"。
  原理：行高被左边照片钉住，名称输入框本身占约 30px，下面再塞一行小字就顶满、没有余量。
  所以名称恢复单行，合计搬到第二行靠右（顺手省掉"合计"两个字）。没填进价 → 那格留空
  （`.pit-amt:empty{display:none}`），不留一条空白。
- ⚠️ **失焦不画框**（老板："名称后失焦后就不要出现那个输入框了 要不然感觉好丑啊"）：

- 数字两格留一层**极淡底**（`--soft`）而不是空白：告诉人"这里能填"，又不至于变回方框。
- ⚠️ **placeholder 就叫「名称」**（老板："名称就名称 为啥还要写一个这货叫什么"）；
  进价框「进价」、件数框「件」、备注框「备注（可空）」。
- 底栏那颗按钮跟着页改称呼：要补的 →「＋ 加一行」，现场进的 →「＋ 记一笔」。

**补货行不动**：那边名称是段文字、点着就能展开，抽屉里有真东西（进价/售价、全名、无此编号），
跟现场行不是一回事 —— 现场行字段全在行上，本来就没东西可摊。

**认货照**：图是按编号存目录的（`imageDir/<编号>/`），新货行还没编号 → 用**临时号**
`_n<时间戳>` 当文件夹，传完记在 `it.img` 上，行上按这个号取缩略图（复用 `receiveImageData`）。
定位是"随手拍一张、下次认得出是它"，不摆拍、不强制。

- **点缩略图 = 看大图**（老板："我要是能够查看这个大图就好了，或者小图也行"）：黑底浮层 `.p-shotview`，
  图用 **`mid`（1024 等比）** 那一档 —— 手机原图实测 7.9MB，`full` 打开要等一下，缩略图又看不清字；
  浮层底下两颗按钮「换一张」（关掉浮层直接重新拍）/「关掉」，点浮层空白处也关。

**口径（很容易踩）**：

- 新货行**不参与**编号排序、不参与"重复编号并进"。
- 导出/复制清单：**补货在前、新货在后**（稳定排序）；名称 = 库里名字优先，没有就用行上手写的；
  Excel 里新货行的「需/差」留空（不能按 拿-0 算成多拿），备注前缀 `进价 ¥9.5 × 12 = ¥114`。
- 数据层：`purchase_item` 加 `name/price/img/kind` 四列（PRAGMA + ALTER 自动迁移，老库老单照读）；
  存库判空从"没编号就丢"改成"**编号和名字都空才丢**"。

**留给以后**（老板："这个功能比较复杂，我就先把简单的先做完"）：新货行以后拿到真编号时，
能不能自动并进那个编号的行 / 能不能**直接入库到商品库**（用新编号建，或替换旧编号的图与价）。
老板 10-17 又强调一次"**这个得十分小心，需要考虑很多**"→ 牵扯到"商品库是别的功能的地基"
（套装、直播排品、图片目录都按编号走），得单开一轮讨论，别顺手做。

加一行 → 点编号格 → 敲编号 → 点需格 → 敲数字 → 收键盘，**一件货四步、还得反复挪手** —— 他宁可不记。

**形态**：底栏那颗 `快速记`（2026-10-17 晚起它是「要补的」那页**唯一**一颗、通栏纯绿底白字 ——
老板原话「加一行不需要了 只需要快速记（纯绿色）」；下面这张是面板本身）→
底部 sheet 「快速记数」：

```
┌────────────────────────────────────┐
│ 快速记数                      完成 │
│ ┌──────────────┐ ┌────┐ ┌──────┐  │
│ │     33       │ │  5 │ │ 加上 │  │
│ └──────────────┘ └────┘ └──────┘  │
│    编号（只敲33也行） 件数 空着＝1  │
│ A033 长款羽绒服 · 已有 需 3 → 加上记 8 │
│ ─────────────────────────────────  │
│ 本次已记 3 笔 · 共 8 件（点 × 撤掉） │
│ (A033+5 ×)(A012+2 ×)(A007+1 ×)      │
└────────────────────────────────────┘
```

**四条口径**（每一条都错了都"在界面上看不出来"，只能靠断言钉）：

- **件数空着＝1**：数到一件顺手补，不用先填个 1。0 / 负数也一律当 1（0 件等于没记，负数会把「需」记成负的）。
- **同一个编号再记一次＝累加**（`qcApply`：`need = before + qty`），不是覆盖 —— 这就是他说"33 号我想加一加一"。
  跟"编号撞车自动并进"同一个意思，只是这里不用先加一行。
- **编号照样归一**：`qcCode()` 走 `canonicalCode(raw) || raw`（只敲 `33` → `A033`，跟行内定稿同一口径）。
  ⚠️ 归一**只在提交时**做，`oninput` 只更提示 —— 边打边归一会把敲下的第一个 `3` 变成 `A003`。
- **「本次已记」可撤**：一笔一个胶囊（倒序，最新在最前），点 × 把那笔的件数减回去。
  ⚠️ 这一行本来就是**这笔新建**的、撤完需又归 0 → **整行删掉**：留一行"编号有、需 0"的空壳
  既不算缺、又会被存进库（`save()` 判空看的是编号和名字都空）。

**敲的路径**：编号 ⏎ → 件数 ⏎（结束回编号框，两个框清空）。
⚠️ 老实说一句：iPhone/Android 的**数字键盘上没有 Return 键**，所以第二跳实际上是他点旁边那颗「加上」
（就在件数右边 7px，还在键盘上方）。Enter 照样接了，是为了外接键盘 / 电脑上开手机版时也能一路敲到底。

**它是模态**（2026-10-17 晚，老板："只要显示确认和完成按钮就行，其他就不能随便点，或者说做成模态窗口"）：

- **点面板外面那层半透明区不再收起**（原来一点就关）。档口一手拿货一手点屏幕，误触一下面板没了 ——
  而"加上了没有"在面板关掉之后是看不出来的（列表里那行本来就该有），他会以为记进去了。
  现在点外面唯一的反应是**把焦点抢回编号框**（从收起键盘的状态点回来，能接着敲）。
- **只有三个出口**：「加上」「取消」「完成」。外面的列表、两段开关、底栏 tab、缺货开关全被遮罩挡住、点不到。
- **「完成」＝留着这一批 + 关面板 + 说一句「已记 N 笔 · 共 M 件」**（2026-10-17 晚老板：
  "我点击了完成，也弹出提示呀 我看你取消都有"）：他点「完成」时其实是在确认"这一批到底进了没有"，
  而面板一关这件事就看不出来了（列表里那行本来就该有）—— 所以这一句就是确认。
  - ⚠️ **必须在 `closeQc()` 之前算**：它会把 `qcLog` 清空，放到后面永远是 0 笔。
  - 一笔没记就点「完成」→ 不弹（跟取消同一条规矩）。
  - 口径跟面板里那行统计一致（`本次已记 N 笔 · 共 M 件`），只是去掉"（点 × 撤掉）"。
- **「取消」＝撤掉本次再关**（2026-10-17 晚，老板："缺少取消按钮 只有完成按钮" → 两个意思里他挑了这个）：
  这次打开面板后记的那几笔**全部撤回去**，回到打开面板之前的样子，再关面板，补一句「已撤掉本次 N 笔」。
  一笔没记就直接关、不弹提示（弹了等于告诉他"我撤了个寂寞"）。
  - ⚠️ 只撤 `qcLog` 里记着的那几笔 —— 不删单子、不碰别人的行（`qcUndoApply` 只把 `need` 减回去）。
  - ⚠️⚠️ **必须倒着撤**（`qcUndoAll`）：同一行记了三次时，最早那笔才知道"这一行是我建出来的"（`created`）。

**与「缺货」筛选的关系**：面板**不清**筛选（跟"加行"不一样）。他开缺货本来就是在数那几款缺的，

## 六、复制清单的文本格式（这是省掉截图的那一步）

```
【补货单 2026-10-15】
A001 白T 中码     需20  拿23  +3
A015 黑裤 L       需10  拿6   -4   ｜档口只剩6条
共 2 款 · 需 30 · 拿 29 · 差 -1
```

**拿齐的行**（需>0 且 拿≥需）前面**自动**加 `✓` —— 不给人勾。

⭐ **差 0 不写差额**（2026-10-16 晚，老板："第四个也可以的，做吧做吧"）：只有差**非 0** 时才在「拿」后面跟 `+3` / `-4`。
正好（拿=需）那一行原来会写成 `需10 拿10 0` —— 那个孤零零的 0 看着像乱码，而且"正好"这个信息对齐的列已经说清了。

⚠️ 口径与**行上那颗差额小字**（`itemDiff`）一致：都是"不相等才出数字"，只是清单里没有颜色，所以只给数字。

## 七、数据模型

照抄直播排品（`live_plan`）那套「一张单 + 有行、有顺序、整张保存」：

```sql
CREATE TABLE IF NOT EXISTS purchase_order (
  id      INTEGER PRIMARY KEY AUTOINCREMENT,
  date    TEXT NOT NULL DEFAULT '',   -- 整单日期 YYYY-MM-DD
  note    TEXT NOT NULL DEFAULT '',   -- 整单备注
  created_at TEXT NOT NULL DEFAULT '',
  updated_at TEXT NOT NULL DEFAULT ''
);
CREATE TABLE IF NOT EXISTS purchase_item (
  order_id INTEGER NOT NULL,
  sort     INTEGER NOT NULL DEFAULT 0,
  code     TEXT NOT NULL DEFAULT '',
  need     REAL NOT NULL DEFAULT 0,
  got      REAL NOT NULL DEFAULT 0,
  done     INTEGER NOT NULL DEFAULT 0,
  note     TEXT NOT NULL DEFAULT '',
  PRIMARY KEY (order_id, sort)
);
```

- 存**编号**不存 `products.id`（跟 `live_star`/`live_plan`/`set_items` 一致，编号是这套系统的锚点）。
- 名称/图片**不落库**，显示时按编号现查 —— 改了商品，单子这边立刻是新的。
- 不需要迁移代码：`CREATE TABLE IF NOT EXISTS` 老库会自动补建。

- ⭐ **点行展开的第二行 = 进价 / 售价**（不再是"商品库里有这个编号"）：库里有 → `进价 ¥88 · 售价 ¥129`；

- ⭐ **顶栏右边两颗图标（放大镜 / 三个点）＝ 白底 + 品牌绿细边 + 绿图形**（2026-10-17 晚改，见上一节），

- ⭐ **「缺货」那颗开关**（在两段开关**右端**，只在「要补的」那页露）：上面那个数字是**还缺的款数**。

  点一下 → 列表只剩还缺的（拿 < 需），**不排序**（仍是编号顺序）；再点一下恢复整单。
  - **一件没拿（拿 0）也算缺** —— 刚开的单整张都是缺的，那时候这条才最有用。
  - 开着的时候：底部汇总换成「缺货 · N 款 · 缺口 M 件」（缺口 = Σ 需−拿，不是把「需」加起来）；

    ⚠️ 三个出口必须一致：屏幕 3 款、发出去 12 款那种事不许有。
  - **一个缺的都没有**时列表给一句话（不是白屏）—— 全拿齐了是很常见的结果。
  - ⚠️ 开着的时候点「导出 Excel」而**一款都不缺** → 弹一句「现在缺货，这单没有缺的款」，

  - 开着的时候点「＋ 记一笔」（现场页那颗）→ 筛选**自动关掉**（那逻辑原本是给"加空行"写的；
    现在要补页已经没有加行按钮了，但这句留着不碍事，切回要补页时不会带着筛选）。
  - 现场那页（新货行）**永远不受这个开关影响**：它们没有「需」，跟"缺"不是一件事。
- ⭐ **加完一行，那一行自动亮**（品牌绿左侧细条 + 淡绿底 + 弹一下），跟"编号并进哪一行 / 排序落到哪"
  **同一个标记**（`.pit.hit`）—— 列表一长不用自己去找它落哪了。一直亮到他开始打字。
- ⭐ **底栏那颗「快速记」＝ 一件一件数着记**（2026-10-17 晚，老板："输入 33 然后边上按钮 + 然后我填多少个"）：
  「要补的」那页它是**唯一一颗、通栏纯绿**（老板："加一行不需要了 只需要快速记（纯绿色）"）。
  点开从底部弹一行 `[编号] [件数] [加上]`。**测法**（照着档口数货的姿势走一遍）：
  1. 敲 `33` → 提示立刻写 `A033 长款羽绒服 · 还没有这一款，加上会新建`（**只敲数字就认**）；
  2. 敲 `⏎` 跳到件数框，敲 `5` → 提示变成「`…需要 需 3 → 加上记 8`」那一类；
  3. 点「加上」→ 两个框**自己清空**、光标**回到编号框**、底下多一个胶囊 `A033+5 ×`；
  4. 紧接着再敲 `33` + 点「加上」（件数**空着**）→ 那一行需**又加 1**（不是变成 1），胶囊多一个 `A033+1 ×`；
  5. 点胶囊上的 `×` → 那 1 件**减回去**；把一笔新建的款整笔撤掉 → **整行从列表里消失**（不留空壳）；
  6. 点「完成」→ 面板收起、**弹一句「已记 N 笔 · 共 M 件」**（跟取消那句对称）、**列表停在最后记过的那一行上（亮着淡绿）**，顶上「缺货 N」和两页款数都变了；
     点面板**外面**那层灰色 → 什么都不该发生（不关面板、也不该点到后面的列表，只有光标回编号框）。
  7. 再打开、记两三笔（含一款单里原来没有的）→ 点左上角「取消」→ 面板关掉、底下提示「已撤掉本次 2 笔」，
     那两款**回到记之前的样子**（单里原来没有的那一款整行消失，不留"需 0"的空壳），退出重进也还是这样。
  7. 退出再进来（或过几秒等自动保存）→ 记的数还在（记完**当场标脏**）。
  ⚠️ 件数框在小键盘上**没有回车键**，第二跳是点旁边那颗「加上」（就在右边 7px）；外接键盘/电脑上可以一路 ⏎。
  ⚠️ 面板**不会**帮你关掉「缺货」筛选：筛着记更好找；只有"加够了"那一行会当场从列表消失（它确实不缺了）。
  ⚠️ 切到「现场进的」那页 → 这颗按钮**自己隐掉**（那页记的是手写名字的新货，没有「需」这回事）。
- **现场记一笔**：一笔占**两行** —— 第一行 `[照片][名称][进价][件]`，第二行 `[备注][¥114][🗑]`。
  写个名字 + 进价 9.5 + 件数 12 → **第二行右端立刻出 `¥114`**（不用自己算）。没填进价时那格是空的、不占位。
- **框只在正在输的那一格出现**：点名称 → 名称周围亮一圈品牌绿；点别处 → 框消失、只剩文字。
  四格都一样（名称/进价/件/备注）。⚠️ 进出格子时**整行不该抖**（边框一直占着位置，只换颜色）。
- **现场行点空白处不会展开**（它没有抽屉）：备注和垃圾桶一直露着，不用先点开。
- **认货照**：点行首那格虚线方框 → 手机弹「相机/相册」→ 拍完方框里出小图。
  有图之后再点 → **黑底大图浮层**，底下「换一张」/「关掉」（点空白处也关）。
- **汇总**：底部那句变成「共 2 款（补货 1 · 新货 1）· 需 20 · 拿 18 · 差 -2 · 新货 ¥114」——
  新货的件数**不掺进需/拿/差**。
- **复制清单 / 导出 Excel**：先列补货行，再列新货行（新货行写 `＋名字 拿12 ¥9.5×12=¥114`）；
  Excel 里新货行的「需/差」是空的，别当成"多拿了"。
- **删行按钮是一个垃圾桶图标**（没有文字）：点一下就删那行 —— ⚠️ 悬而未决：要不要加确认框。
- **编号只敲数字也能用**：敲 `6` / `06` / `006`，一离开这一格（点别处、Tab、回车）就**当场变成 `A006`**，
  名称和图立刻出来（不用敲那前面的 A）。`000`、`XD` 这种归一不了的保持原样、照旧提示「无此编号」。
- 需求/实拿/备注改完能存住，重进还在（边改边存，返回/切 tab 会立刻结算一次）。
- 顶部汇总与整单状态随行变化（差 +3 / 差 -4；已完成 / 已齐 x/y / 未开始）。
  ⚠️ **没有手工勾**了：需 20 拿 20 → 这行自动算"齐"，复制清单里自动带 `✓`。
- 「复制清单」出来的文本格式如第六节，贴到微信里**列要对齐**。
