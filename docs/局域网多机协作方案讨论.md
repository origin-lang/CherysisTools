# 局域网多机协作方案讨论

> 讨论时间：2026-09-20
> 状态：方案 A 已实施并交付团队；方案 B 已设计存档，尚未实现（见 [http-中继方案-设计.md](http-中继方案-设计.md)）

---

## 背景

- **团队规模**：2-3人（你 + 团队成员）
- **使用场景**：同一办公室局域网，每个人都需要录入和查看商品数据
- **出门后**：只有主机能用，其他人不能用（可接受）
- **费用**：不想花钱
- **技术水平**：会用 Git/npm，团队成员已装好扩展
- **数据重要性**：重要，不能丢
- **写入模式**：多人都会写，但冲突概率低

---

## 方案对比

### 方案 A：共享文件夹（推荐先试）

**原理**：
```
电脑A（主机）：共享 D:\shopData 文件夹
电脑B/C：映射网络驱动器 \\192.168.1.100\shopData → Z:
所有人的扩展都指向 Z:\shop.db
```

**优点**：
- ✅ 零代码部署
- ✅ 不需要额外服务
- ✅ 团队成员只需知道共享文件夹路径
- ✅ 和现在使用体验几乎一样

**缺点**：
- ❌ 必须在同一局域网
- ❌ 主机必须开着
- ❌ 有小概率锁冲突

**风险**：
| 风险 | 概率 | 后果 |
|------|------|------|
| 两人同时改同一条 | 低 | 一个报错，重试即可 |
| 写入时网络断开 | 极低 | 丢最后几毫秒的数据 |
| 数据库损坏 | 极低 | 从备份恢复 |

**SQLite 官方警告**：
> "Rely upon it at (your and your customers') peril."
> （用网络文件系统共享 SQLite，后果自负。）

**缓解措施**：
1. 把 WAL 模式改成回滚模式（journal_mode=DELETE）
2. 加重试逻辑（遇到 SQLITE_BUSY 自动重试3次）
3. 定期备份 shop.db

---

### 方案 B：HTTP 中继（如果方案 A 出问题）

**原理**：
```
电脑A（主机）：运行 HTTP 服务，监听端口13800
电脑B/C：通过 HTTP 请求访问主机的数据库
```

**优点**：
- ✅ 数据安全（单一数据源，无锁冲突）
- ✅ 可以扩展到互联网（加内网穿透）

**缺点**：
- ❌ 主机需要运行服务进程
- ❌ 实现复杂（约200-300行代码）
- ❌ 主机挂了其他人无法使用

**需要的文件**：
- `src/core/httpServer.ts` — HTTP 服务端
- `src/core/httpClient.ts` — HTTP 客户端
- `src/tools/shopTool/dbBridge.ts` — 数据库方法映射

**API 设计**：
```
POST /api/shop/invoke
Body: { method: "getProducts", args: [] }
Response: { ok: true, result: ... }
```

---

### 方案 C：WPS 多维表格（放弃）

**原因**：
- WPS 多维表格是通用工具，没有你的定制功能
- 你的 shopTool 有编号规则、批量操作、星标总览、导出图片等专属功能
- 数据放在第三方服务器上，你可能不放心

## 实施步骤（方案 A）

### 第一步：主机共享文件夹

1. 在主机上创建文件夹，比如 `D:\shopData`
2. 把这个文件夹共享出去：
   - 右键文件夹 → 属性 → 共享
   - 添加 Everyone → 读写权限
3. 记下主机的 IP 地址（比如 `192.168.1.100`）

### 第二步：其他电脑映射网络驱动器

1. 文件资源管理器 → 右键"此电脑" → "映射网络驱动器"
2. 输入 `\\192.168.1.100\shopData`
3. 勾选"登录时重新连接"
4. 完成后会多一个盘符（比如 Z:）

### 第三步：配置扩展

1. 每台电脑的 VS Code 设置里，把 `cherysis.storageDir` 改成 `Z:\`
2. 重启 VS Code

### 第四步：改代码（我来做）

1. 把 WAL 模式改成回滚模式
2. 加重试逻辑
3. 打包新版本
