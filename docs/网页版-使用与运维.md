## 一、它是什么

同一套业务内核，换了一层皮。**商品/图片/规则的逻辑只有一份**（`src/tools/shopTool/handlers/`），
电脑版（VS Code）和网页版都调它。网页版新增的只有两块：

- `src/server/` —— 一个极薄的 HTTP 服务：把浏览器请求包装成 handler 认的 `ctx`，
  再把 handler 原本要 `postToWebview` / `log` 出去的东西收成 JSON 返回。**业务逻辑一行没重写**。
  其中三个是纯逻辑模块，跟 http 无关，可以单独测：
  `events.ts`（实时推送中枢）、`serialQueue.ts`（串行队列）、`taskQueue.ts`（重活排队）。
- `src/webview/mobile/` —— 三个静态文件（`index.html` / `app.js` / `style.css`），只管显示。

这么做的唯一理由是**防口径漂移**：如果两边各写一遍"售价怎么算""编号 L1~L33 怎么解析"，
半年后一定对不上。所以编号语法虽然物理上有两份，`scripts/check-shopTool-parity.cjs`
会逐字比对，不一致就报错。

```
手机浏览器 ──HTTP──→ src/server ──→ shopTool handlers ──→ shop.db / 图片目录
   ↑  实时推送（SSE /api/events）：日志、进度、别人的改动、重活排队
VS Code 版 ────────────────────────↗（同一层内核）
```

## 二、启动

### 最省事的办法：双击

根目录的 **`启动网页版.cmd`**（双击即可）。它会切到项目目录、检查配置、必要时先编译，
然后把服务跑起来并把手机地址打印出来。**关掉那个窗口 = 停止服务**。

第一次用之前要先有配置文件：把 **`cherysis-server.config.example.json`** 复制一份、
改名成 `cherysis-server.config.json`，把里面的三个路径改成**跑服务这台机器**上的真实路径。
（配置文件里都是本机路径、可能有口令，所以 **不进仓库**。）

| 参数 | 作用 |
| --- | --- |
| `storageDir` | `shop.db` 所在目录（多人共享时就是共享盘上那个） |
| `imageDir` | 商品图片根目录，**每个商品一个子文件夹**（按编号命名） |
| `cacheDir` | 服务端**本机**的缩略图缓存 + 偏好文件，**别指向共享盘**（慢、会互相踩） |
| `liveOutDir` | 九宫格/星标总览的输出目录（服务端路径，网页上只读展示） |
| `port` / `host` | 监听端口/地址（默认 13800；现在实际在用 666） |
| `token` | 共享口令；不填 = 不校验（见 §五） |

### 命令行（调试时用）

```bash
pnpm run compile          # 改了 src 下的 .ts 必须先编译（跑的是 out/）
pnpm run serve            # 等价 node out/server/index.js，读同目录的 cherysis-server.config.json
# 或者显式给参数：
node out/server/index.js --port=666 --storage-dir=D:\数据 --image-dir=D:\商品图片 --cache-dir=C:\Users\你\cherysis-cache
```

配置优先级：**命令行 > 环境变量 > 配置文件**。
⚠️ 配置文件是相对**启动时的工作目录**找的：从别的地方启动就加 `--config=配置文件的绝对路径`
（`启动网页版.cmd` 已经这么做了）。

### 开机自启

任务计划程序 → 触发器"登录时"（要"没人登录也跑"就选"计算机启动时"+勾"不管用户是否登录"）→
程序 `node.exe`，参数 `out\server\index.js --config=配置文件的绝对路径`，起始位置填项目目录。

## 三、手机连上去

1. 服务启动后会打印**局域网地址**（如 `http://192.168.x.x:666`），手机连同一个 Wi-Fi 打开即可。
2. **Windows 防火墙要放行 666**：需管理员 PowerShell 自行加规则（助手工具无权提权）。
3. 连不上时按顺序排查：主机 IP 变了？手机和主机同网段？防火墙？先访问 `http://<IP>:666/api/ping`。
4. 底部那条细条右边有一盏**连接灯**：绿=已连接、灰=重连中、红=已断开。
   断线不用管，浏览器的 EventSource 会自己重连（并自动补上断线期间漏掉的事件）。

## 四、日常怎么用

| 想干什么 | 怎么走 |
| --- | --- |
| **录新品** | ＋新建 →「用下一个空号」→ 📷拍照（当场能删能重拍）→ 填进价/售价/库存 → 保存，照片自动挂上去 |
| **盘点 / 改数** | 列表视图：点那一格**选中**，再点一下弹输入框（状态列点一下直接切） |
| **找一行** | 顶部搜索 = "凭印象找一行"（子串匹配） |
| **勾一批** | 展开筛选：品类/系列/等级/状态/数值范围/有图无图；条件会变成顶部的 pill，点 ✕ 撤一条 |
| **看款式** | 画册视图（卡片显示"进价 → 售价"和库存） |
| **看图 / 传图 / 删图** | 点编号进详情；📷传图；缩略图右上角 ✕ 删 |
| **看规则、改规则** | ⚙ 里是**只读**的，要改去电脑版（VS Code 插件 → 商品管理 →「规则与设置」） |
| **别人改过数据** | 不用管：同过网页改的会**自动变**；电脑版改的会在底部亮 **「🔄 有改动」**，点一下重读 |

编号范围（`L1~L33` 这种）属于**条件不是搜索**，在筛选区里填。

## 五、实时推送与并发（第 21~24 批之后的现状）

**已经有实时推送了**（`/api/events`，SSE）。手机上会自动发生这些事：

| 什么时候 | 手机上的表现 |
| --- | --- |
| 别人（另一台手机/客机浏览器）改了数据 | 那一条**自动变**（服务端把改动广播出来了），不用点刷新 |
| **电脑版**（VS Code）改了数据 | 服务端没有这条广播可发，但它每 3 秒巡检一次数据库版本，一变就在底部亮 **「🔄 有改动」**。点它 = 重新读一遍 |
| 服务端的后台长任务在跑（如生成共享缩略图） | 进度逐条进【日志】；点了按钮的那台手机也收得到 |
| 断线（锁屏、切后台、服务重启） | 灯变灰/红并自动重连；断太久补不齐时会整表重读一次 |
| 有人点了重活（生成缩略图等） | `queue` 事件：日志里出现「⏳正在生成 X」；同一时刻只跑一个 |

**写保护做到哪一步了**：
- 服务端**自己**的写请求已经排队（同一时刻只有一个写进内核），两个人同时保存不会再交错。
- 跨进程（电脑版也开着同一个库）仍然靠 SQLite 的文件锁 + 10 秒忙等 + 重试 —— 超出等待窗口会**明确报错给你看**，不会静默丢数据。
- **字段级冲突拦截没做**（本期定论）：后写覆盖先写，但有「有改动」提示。
- ⚠️ **电脑版的"撤销"是整库快照回写**：它会把网页版刚写的东西一起覆盖回去。用完网页版改数据后，
  电脑版那边尽量别急着撤销（这是现在的真实语义，不是 bug）。

**还没做的**：
1. **`size=grid`（1024 排品图）** —— 给排品/九宫格预览省流量用，与售价计算无关。
2. **手机上的出图入口**（九宫格/星标总览）：服务端已经具备（队列 + 进度推送都就位），
   缺的是页面上的按钮；星标总览成品还要先选输出目录，网页版选不了，需另想办法。
3. **PWA / 离线**（M3）。
4. **token 默认关着** —— 局域网里谁都能打开。要上锁：配置文件里写 `"token": "口令"`（或 `--token=口令`），
   手机第一次访问用 `http://<IP>:端口/?token=口令`，前端会把口令记在浏览器里，之后存书签直接进。

其他已知：表格**没有图片列**（看图去画册，见设计稿 §十二·补 第 12 条）；
删图偶尔失败多半是别的机器正占着那张图，等几秒重试即可（第一张是封面，被读得最勤，最容易撞上）。

## 六、改代码之后

| 改了哪里 | 要做什么 |
| --- | --- |
| `src/webview/mobile/*`（前端三件套） | **不用编译**，静态资源是 `no-cache` 直出，刷新即可 |
| `src/**/*.ts`（含 `src/server`、handlers） | 必须 `pnpm run compile`，然后**重启服务**才生效 |
| 编号语法 / 字段规则 | `pnpm run check:parity`（已挂进 `pretest` 与 `vscode:prepublish`） |
| 服务端纯模块（推送/队列） | `pnpm run check:server`（34 组用例，不需要起服务、不碰数据库） |
| 手机版页面（DOM id、SSE 事件名） | `pnpm run check:mobile` |
| 长活儿接缝（VS Code 侧的老语义） | `pnpm run check:longtask`（用假 ctx 直接调真 handler：不 await 直接开跑、`generateLiveGrid` 返回 Promise） |
| 全部 | `pnpm run lint`，或 `pnpm test`（pretest 会把上面几条全跑一遍） |

`check:mobile` 是替代原来"改完 app.js 手动对一遍 DOM id"的：它会核对
`$("xxx")` 的每个 id 在 `index.html` 里存在（`codeQ` / `fsInput` 是 JS 动态生成的，已豁免），
**并且**核对 SSE 事件名前后端对得上 —— 这两个都是拼错一个字母就静默失效、日志里什么都没有的类型。

`check:longtask` 是因为**完整测试套件在这台机器上跑不起来**才补的（详见下一节）。

## 七、自检与排查

> ⚠️ **`pnpm test`（完整的 VS Code 测试套件）在开发这台机器上跑不起来**：
> VS Code 的扩展宿主拿不到可写的 `%TEMP%`，测试文件在加载阶段就 `EPERM: mkdtemp`，
> 早于任何被测代码执行 —— 是环境限制，不是测试或代码的问题（升权重试过一次，同样卡在这一步）。
> 所以本轮的替代证据是：`compile` + `lint` + 上面四条闸门（parity / server / mobile / longtask），
> 外加下面三个对着**真服务**跑的端到端脚本。要跑完整套件，请在能正常起 VS Code 的机器上
> `pnpm test`。

`/api/ping` 会把服务端的状态直接回给你，**出问题时先看它**（浏览器打开 `http://<IP>:端口/api/ping`）：

| 字段 | 怎么看 |
| --- | --- |
| `imageDirReady` | `false` = 图片根目录没配或不存在 → 看图相关的都会报错 |
| `tokenRequired` | `true` 时所有 `/api/*` 都要带 `?token=` |
| `eventClients` | 手机到底连上没有。`0` = 一个实时连接都没有 → 看手机端提示 |
| `rev` | 库的版本号（真改动才 +1）；`dataVersion` 是 SQLite 那边看到的"别人改过"计数 |
| `writeQueue` | 写队列深度。持续 >0 = 有写卡住了（多半是共享盘慢） |
| `tasks` | `running` / `waiting`：重活是不是在排队（「点了没反应」多半是这里） |

对着**测试库**跑的三个端到端脚本（会真的写测试库，所以默认拒绝指向正式库，除非 `--force`）：

```bash
# 先起测试服务（667 + tmp-web-test 三个路径）
node scripts/e2e-web-realtime.cjs     # 实时推送四件事：广播到旁观者 / 不重复打扰 / 巡检发现外部改动 / 并发写不丢
node scripts/e2e-web-fingerprint.cjs  # rev 的判据：真改动认得出、没改动不乱报
node scripts/e2e-web-tasks.cjs        # 长任务：请求立刻返回、queue 事件、进度推到手机、队列回空闲
```

常见现象对症：

| 现象 | 先看 |
| --- | --- |
| 手机打不开页面 | 服务在跑吗？同网段吗？防火墙？`/api/ping` 通不通 |
| 能打开但图片全是空白 | `imageDirReady`；图片根目录下是不是"每个商品一个子文件夹" |
| 别人改了这边不变 | 底部连接灯什么颜色？`eventClients` 是不是 0？对方那次改动是否有回推（没回推时会亮「有改动」而不是自动变） |
| 电脑版改了不提示 | `/api/ping` 的 `dataVersion` 有没有在变；不变说明服务端压根没看见外部改动 |
| 点了生成没反应 | `/api/ping` 的 `tasks`：在排队就等，`running` 空着还没动就是异常，看日志 |

## 八、测试环境 vs 正式库

仓库内的 `tmp-web-test/`（种子脚本造的 160 条假数据 + 假图）是**演示/自检用**的，不是正式商品库。
切到正式库就是把配置文件里的 `storageDir` / `imageDir` 换成真实路径、重启服务 ——
**不需要再造测试数据**。

⚠️ 切之前先备份 `shop.db`（插件本身有自动备份 + 操作前备份，双保险更稳）。
`cacheDir` 要留在**跑服务这台机器的本机盘**，别跟着数据一起放共享盘。

造测试数据的脚本：

```bash
node scripts/seedShopProducts.cjs <shop.db 路径> 160   # 造商品（第二个参数=目标条数）
node scripts/seedProductCovers.cjs <shop.db 路径>      # 造封面图（读库里 settings.image_dir，先设好）
```
