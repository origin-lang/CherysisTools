## 一、它是什么

同一套业务内核，换了一层皮。**商品/图片/规则的逻辑只有一份**（`src/tools/shopTool/handlers/`），
电脑版（VS Code）和网页版都调它。网页版新增的只有两块：

- `src/server/` —— 一个极薄的 HTTP 服务：把浏览器请求包装成 handler 认的 `ctx`，
  再把 handler 原本要 `postToWebview` / `log` 出去的东西收成 JSON 返回。**业务逻辑一行没重写**。
  其中三个是纯逻辑模块，跟 http 无关，可以单独测：
  `events.ts`（实时推送中枢）、`serialQueue.ts`（串行队列）、`taskQueue.ts`（重活排队）。
- `src/webview/mobile/` —— 三个静态文件（`index.html` / `app.js` / `style.css`），只管显示。

这么做的唯一理由是**防口径漂移**：如果两边各写一遍"售价怎么算""编号 A1~A33 怎么解析"，
半年后一定对不上。所以编号语法虽然物理上有两份，`scripts/check-shopTool-parity.cjs`
会逐字比对，不一致就报错。

```
手机浏览器 ──HTTP──→ src/server ──→ shopTool handlers ──→ shop.db / 图片目录
   ↑  实时推送（SSE /api/events）：日志、进度、别人的改动、重活排队
VS Code 版 ────────────────────────↗（同一层内核）
```

## 二、启动

### 最省事的办法：双击

根目录的 **`启动网页版.cmd`**（双击即可）。它会切到项目目录、检查配置、必要时先编译，
然后把服务跑起来并把手机地址打印出来。**关掉那个窗口 = 停止服务**。

第一次用之前要先有配置文件：把 **`cherysis-server.config.example.json`** 复制一份、
改名成 `cherysis-server.config.json`，把里面的三个路径改成**跑服务这台机器**上的真实路径。
（配置文件里都是本机路径、可能有口令，所以 **不进仓库**。）

| 参数 | 作用 |
| --- | --- |
| `storageDir` | `shop.db` 所在目录（多人共享时就是共享盘上那个） |
| `imageDir` | 商品图片根目录，**每个商品一个子文件夹**（按编号命名） |
| `cacheDir` | 服务端**本机**的缩略图缓存 + 偏好文件，**别指向共享盘**（慢、会互相踩） |
| `liveOutDir` | 九宫格/星标总览的输出目录（服务端路径，网页上只读展示） |
| `port` / `host` | 监听端口/地址（默认 13800；现在实际在用 666） |
| `token` | 共享口令；不填 = 不校验（见 §五） |

### 命令行（调试时用）

```bash
pnpm run compile          # 改了 src 下的 .ts 必须先编译（跑的是 out/）
pnpm run serve            # 等价 node out/server/index.js，读同目录的 cherysis-server.config.json
# 或者显式给参数：
node out/server/index.js --port=666 --storage-dir=D:\数据 --image-dir=D:\商品图片 --cache-dir=C:\Users\你\cherysis-cache
```

配置优先级：**命令行 > 环境变量 > 配置文件**。
⚠️ 配置文件是相对**启动时的工作目录**找的：从别的地方启动就加 `--config=配置文件的绝对路径`
（`启动网页版.cmd` 已经这么做了）。

### 开机自启

任务计划程序 → 触发器"登录时"（要"没人登录也跑"就选"计算机启动时"+勾"不管用户是否登录"）→
程序 `node.exe`，参数 `out\server\index.js --config=配置文件的绝对路径`，起始位置填项目目录。

## 三、手机连上去

1. 服务启动后会打印**局域网地址**（如 `http://192.168.x.x:666`），手机连同一个 Wi-Fi 打开即可。
2. **Windows 防火墙要放行 666**：需管理员 PowerShell 自行加规则（助手工具无权提权）。
3. 连不上时按顺序排查：主机 IP 变了？手机和主机同网段？防火墙？先访问 `http://<IP>:666/api/ping`。
4. 底部 tab 栏右边有一盏**连接灯**（一个小圆点）：绿=已连接、灰=重连中、红=已断开。
   断线不用管，浏览器的 EventSource 会自己重连（并自动补上断线期间漏掉的事件）。

## 3b、外网访问（不在同一个 Wi-Fi 也能开）

服务启动时会**自己起一条 Cloudflare 快速隧道**，并在控制台打印一个 `https://xxx.trycloudflare.com`。
外面的人（手机流量、别人家电脑）直接打开这个地址，**什么都不用装**。

```
☁️  外网访问（外面的人直接开这个，手机电脑都不用装东西）：
     https://css-africa-roots-achievement.trycloudflare.com
     ⚠️地址每次重启都会换；现在没有门禁，别转发到群里
```

三件事必须心里有数：

| 事实 | 后果 |
|---|---|
| 隧道是**独立常驻**的（脱钩，不跟服务同生共死） | **重启服务不换地址**，已经发出去的链接继续有效；只有**重启电脑**、或隧道真崩了才会换 |
| 服务关了但隧道还在 | 外面打开会得到 **502**（不是打不开）。想真正关掉外网，得写 `tunnel: false` 再启动一次 |
| **外网要密码**（配置文件里的 `password`） | 只拦**从隧道进来的**请求；局域网和本机不弹。同一 IP **5 分钟内错 10 次 → 关 24 小时**（局域网里点「解除」才放行） |
| 快慢取决于**你家宽带的上行** | 实测首页 ~1.4s、缩略图 ~1.2s/张（延时全在到 Cloudflare 边缘的往返上，本地同一请求只要 6ms） |

**密码怎么设 / 怎么改**：
```json
// cherysis-server.config.json
{ "password": "202610171997" }
```
- **密码规则（约定）**：`当天日期 YYYYMMDD + 1997`。例 2026-10-17 → `202610171997`。
  想换就照这个规则改，别用生日、手机号、门牌号 —— 前两种一猜就到，最后一种发给别人等于告诉他你住哪。
- 留空 = 不设门禁（谁拿到链接谁能改库，只在完全信任的场合这样用）
- **改密码会让所有人立刻重新登录**：cookie 里的签名密钥是从密码派生的，老票自动作废，不用挨个踢
- 登录一次记 30 天；登录页在 `/login`
- **启动横幅会把密码直接打出来**（`🔒 密码：xxxx`）——那窗口在本机，只有你看见；
  好处是发链接时不用再翻配置文件。⚠️ 别把那个窗口截图发出去。
- 判据是 Cloudflare 加的 `cf-ray` / `cf-connecting-ip` 头，**不能**按来源 IP 判 ——
  请求是 cloudflared 在本机转发的，源地址永远是 `127.0.0.1`
- ⚠️ 密码是**写死在配置里的**，不会自己按日期滚动。理由：一天一换意味着每天都要重新告诉人，
  而且和已经发出去的密码对不上 —— 换来的是麻烦，不是安全。

**防爆破（2026-10-17 晚加）**：密码是「日期+1997」这种东西，光靠密码本身挡不住脚本试。

| 规则 | 具体 | 为什么这么定 |
|---|---|---|
| 计数窗口 | 同一 IP **5 分钟内**错满 **10 次** | 一分钟 10 次太松（一分钟能试十遍），5 分钟 10 次对正常手抖完全够 |
| 锁多久 | **24 小时**，从**最后一次**试错起算 | 他的原话：「自己人不可能超过 10 次」→ 错满基本就是有人在外面试。从第一次算的话，慢慢试的人（4 分钟才凑够 10 次）只需再等一会儿就放出来了 = 等于没锁 |
| 锁着的时候 | 连**密码对了也不给过**（429，不是 401） | 否则爆破的人照样能一点点试 |
| 锁满以后 | 计数清零，重新开始 | 不然攒够 10 次就永久进不去，正常用户会被自己坑死 |
| 慢慢试 | 每次隔一分钟错一次 → 不锁 | 每个窗口里最多 5 次，够不着 10 次 |
| 局域网 / 本机 | **完全不受影响** | 限速只对带 `cf-connecting-ip` 的隧道请求生效 |
| 记在哪 | `<cacheDir>/gate-locks.json`（**落盘**） | 不落盘的话，重启一次服务就把 24 小时的锁洗掉了 —— 这道锁等于没设 |
| 怎么放人 | **只能在局域网**操作：网页版 → ⚙ 设置 → 系统配置 →「服务」→「封禁」那一行点**解除** | 他说「必须后台操作才能让他进」。外网来的解除请求一律 401/403，否则被封的人自己点一下就解了 |

- 撞线那一次就回 429 + `Retry-After`，登录页上直接写「**试太多次了，24 小时后再来**」，
  不用他再点一次才知道被锁。
- 服务重启时启动日志会打一行：`🔒 有 N 个 IP 还在封禁中…要放人进来：局域网打开网页版…`
- 副作用（可接受）：拿到链接的人可以故意连错 10 次，把你（外网）挡 24 小时。
  代价是「外网进不来」，不是「完全进不来」—— 家里/店里走局域网一直能进，点一下「解除」也立刻恢复。
- 他自己被锁了怎么办：局域网打开网页版的设置页点解除（外网进不来时，手机连店里 Wi-Fi 一样能开）。

**接管是怎么回事**：隧道进程号、当前地址、指向的端口，都存在
`%LOCALAPPDATA%\cherysis-server\tunnel.meta.json`。服务启动时先读它：**进程还活着 + 端口对得上 → 直接接管，不重起**
（重起就换地址）。所以别删这个文件，也别手动改它。

**关掉它**（三种写法任选，改完重启服务；这时会连遗留的隧道一起杀掉）：
```json
// cherysis-server.config.json
{ "tunnel": false }
```
或 `--tunnel=0`，或环境变量 `CHERYSIS_TUNNEL=0`。

**二进制在哪**：`%LOCALAPPDATA%\cherysis-server\bin\cloudflared.exe`（约 53MB，不进 vsix）。
换机器部署时要么把这份复制过去，要么让它显示「没找到 cloudflared」并关掉外网访问 —— 后者不影响局域网使用。

**面板上也有一行**（VS Code → 网页版服务 → 外网访问）：地址 + 复制 + 在浏览器打开，
每 5 秒刷新。⚠️ 面板只显示**服务刚给的那一个**，不要缓存到文件 —— 存下来的那个下次一定是死的。

**手机上也看得到（2026-10-17 加）**：手机浏览器打开网页版 → 底部「⚙ 设置」→「**系统配置**」页签 →
最下面「**服务**」卡片，在「需要口令」那几行后面会多出两行：

```
内网   http://192.168.1.40:667                                  [复制]
外网   https://xxxx-yyyy-zzzz.trycloudflare.com                 [复制]
```

- 内网那行是**这台机器当前的局域网地址**（换 Wi-Fi/换网段会变，所以每次都现算，不写死）。
- 外网那行只在隧道起来后才有；还在连的时候显示「正在连接…」，连不上显示原因（比如「隧道断了，30 秒后重连」）。
  **配置里写了 `tunnel: false` 就整行不出现**（关了外网的人不该看到幽灵行）。
- 两颗「复制」都是点了变「已复制」再变回来。⚠️ 局域网是 **http**，
  `navigator.clipboard` 在非 https 下**不存在**，所以走的是 `textarea + execCommand` 那条降级路 ——
  改这段别把它当成"旧写法"删掉，删了他在家里 Wi-Fi 下就复制不了。
- 有 IP 被封（错满 10 次密码）时，这下面会多几行「封禁 / 还剩 N 小时 / [解除]」。
  ⚠️ **只有局域网打开才看得到**：外网来的 `/api/ping` 里这一项永远是空的，点解除也只会被拒。

## 四、日常怎么用

| 想干什么 | 怎么走 |
| --- | --- |
| **录新品** | 顶栏那个绿色「＋」→「用下一个空号」→ 📷加图片（当场能删能重拍，弹的是系统相机/相册选择器）→ 填进价/售价/库存 → 保存，照片自动挂上去 |
| **盘点 / 改数** | 列表视图：点那一格**选中**，再点一下弹输入框（状态列是个**胶囊标签**，点一下直接切） |
| **找一行** | 顶部搜索 = "凭印象找一行"；左边「搜哪一列」切到**编号**时改吃区间写法（`A1~A33`，**回车/点别处才生效**） |
| **勾一批** | 展开筛选：品类/系列/等级/状态/数值范围/有图无图；**每组折成一行**（点标题展开，收起来时右边写着这组当前选了什么）；条件会变成顶部的 pill，点 ✕ 撤一条 |
| **看款式** | 画册视图（卡片显示"进价 → 售价"和库存） |
| **看图 / 传图 / 删图** | 点编号进详情；右上角 📷 加图（相机/相册）；缩略图右上角 ✕ 删 |
| **看规则、改规则** | 底部「⚙ 设置」里是**只读**的（三个页签：系统配置 / 页面配置 / 日志），要改去电脑版（VS Code 插件 → 商品管理 →「规则与设置」） |
| **别人改过数据** | 不用管：同过网页改的会**自动变**；电脑版改的会在底部「**设置**」格右上角亮一个**小红点**（2026-10-12 起：原先是底部那条细条上的「🔄 有改动」按钮）。要手动重读：设置 → 系统配置 →「🔄 重新从数据库读一遍」 |

### 搜索行：选哪一列，右边的控件就跟着换（和电脑版一个口径）

顶部搜索行是「**搜哪一列**下拉（全部/编号/名称/品类/系列/等级/状态）＋ 右边控件」。
**选到哪一列，右边的东西就换成适合那种值的样子** —— 这样不用为了同一件事开两个入口：

| 选到 | 右边变成 | 怎么用 |
| --- | --- | --- |
| 全部 / 名称 / 系列 | 文字框（默认形态） | 子串模糊找。系列的值太多，不给做成一长条下拉 |
| **编号** | 同一个文字框改吃**区间语法** | `A1~A33`（全角「～」也认）、单写 `A1` = 找 A001、`A1~A33,B1~B22` 逗号分段。**回车或点别处生效**（打字中途不筛 —— `A` → `A1` → `A1~` 一路闪无效中间态很难受）。框下面有一行提示告诉你这句认不认 |
| **状态** | 下拉（全部状态 / 在售 / 已下架） | 状态只有两个值，让用户手打中文等于让他猜系统里存的是哪两个字；**选完立刻生效**，不用回车 |
| **品类 / 等级** | 下拉（全部品类 / 各品类，带个数） | 值就那么几个，选比手打准（手打中文错一个字就是个空表）；**选完立刻生效**，不用回车。⚠️ 2026-10-12 从「一排圆片」改成下拉 —— 商家不要圆圈圈，跟电脑端统一；**圆圈只留在筛选面板里**（那边能多选，这个下拉是单选，面板里勾多个时它只显示其中一个） |

「编号」这一列**只有搜索行一个入口**了（原先筛选面板里那组「编号范围」加三行说明已经并了过来）——
同一件事有两个入口最容易让人搞不清该填哪个。

### 筛选面板：每组折成一行

面板里十来组（品类 / 系列 / 等级 / 状态 / 类型 / 图片 / 进价 / 售价 / 库存…）默认**只展开「品类」**，
其余折起来，组名一屏看得全。**点组标题**展开或收起；收起时标题右边写着这组**当前筛了什么**
（离散列写选中的名字，数值列写 `10~30` / `≥ 10` / `≤ 30`，没筛就写「未筛」），所以折起来也不会"忘了自己筛过什么"。

> 折叠的是**长相**，不是条件：折起来照样生效，有条件照样变成顶部的 pill。

**搜索行和筛选面板是「且」的关系**：搜索是"凭印象找一行"，筛选是"一批一批挑出来"，两个一起开就 AND。
两边**共用同一份条件**：在搜索行那个下拉里选「品类」，面板里品类那组也会同步亮起来（反之亦然）。

## 五、实时推送与并发（第 21~24 批之后的现状）

**已经有实时推送了**（`/api/events`，SSE）。手机上会自动发生这些事：

| 什么时候 | 手机上的表现 |
| --- | --- |
| 别人（另一台手机/客机浏览器）改了数据 | 那一条**自动变**（服务端把改动广播出来了），不用点刷新 |
| **电脑版**（VS Code）改了数据 | 服务端没有这条广播可发，但它每 3 秒巡检一次数据库版本，一变就在底部「**设置**」格右上角亮一个**小红点**（列表本身会自动刷新，红点只是告诉你「刚才有别人动过」）。要手动重读：设置 → 系统配置 →「🔄 重新从数据库读一遍」 |
| 服务端的后台长任务在跑（如生成共享缩略图） | 进度逐条进「设置 → 日志」页签；点了按钮的那台手机也收得到 |
| 断线（锁屏、切后台、服务重启） | 连接灯变灰/红并自动重连；断太久补不齐时会整表重读一次 |
| 有人点了重活（生成缩略图等） | `queue` 事件：日志里出现「⏳正在生成 X」；同一时刻只跑一个 |

**写保护做到哪一步了**：
- 服务端**自己**的写请求已经排队（同一时刻只有一个写进内核），两个人同时保存不会再交错。
- 跨进程（电脑版也开着同一个库）仍然靠 SQLite 的文件锁 + 10 秒忙等 + 重试 —— 超出等待窗口会**明确报错给你看**，不会静默丢数据。
- **字段级冲突拦截没做**（本期定论）：后写覆盖先写，但底部「设置」格上会冒小红点提示你。
- ⚠️ **电脑版的"撤销"是整库快照回写**：它会把网页版刚写的东西一起覆盖回去。用完网页版改数据后，
  电脑版那边尽量别急着撤销（这是现在的真实语义，不是 bug）。

**还没做的**：
1. **`size=grid`（1024 排品图）** —— 给排品/九宫格预览省流量用，与售价计算无关。
2. **手机上的出图入口**（九宫格/星标总览）：服务端已经具备（队列 + 进度推送都就位），
   缺的是页面上的按钮；星标总览成品还要先选输出目录，网页版选不了，需另想办法。
3. **PWA / 离线**（M3）。
4. **token 默认关着** —— 局域网里谁都能打开。要上锁：配置文件里写 `"token": "口令"`（或 `--token=口令`），
   手机第一次访问用 `http://<IP>:端口/?token=口令`，前端会把口令记在浏览器里，之后存书签直接进。

### 5.1 长任务的结果只回给「点按钮的那一台」（2026-10-17 晚）

病：手机上点「导出 Excel」，**电脑上那个页面也弹一次下载**（电脑版 panel 不受影响，它是另一条通道）。

根因在 `EventHub.publish`：它原来只有一条规则 —— **跳过与发信人同源的连接，其余全发**。
而长任务（导出）走 `longTask → 服务端队列`，`/api/invoke` 早就回完了，`makeRequestSink` 会把
`origin` 清成 `""`（表示"服务端自己发的"）→ **连"跳过自己"这条都失效，于是谁连着谁就收**。
而那个 base64 有一两 MB，白推给每一台设备，前端一收到就 `URL.createObjectURL` + `<a download>`。

修法（`HubEvent.target`）：

| 层 | 变成什么样 |
| --- | --- |
| `ToolContext` / `HandlerCtx` | `post(msg, opts?)` / `log(text, opts?)`，`opts.toRequester = true` = 只回发起人 |
| `handlers/purchase.ts` | 导出那条路**全走** `postMe` / `logMe`（三条终态 + 进度日志）。日志也算：否则别人的日志区会冒出你没点过的导出记录 |
| `httpHost.makeRequestSink` | 请求还在飞 → **一条都不推**（结果随响应回去，推了就是应用两遍）；已脱钩 → `target = clientId` |
| `EventHub.publish` | 有 `target`：只发给它，且**不按 origin 跳过**；无 `target`：老规则不变 |

三条代价，都是明知故犯：
1. **定向帧不进环形缓冲** —— 一两 MB × 200 条能把内存顶爆，而且补发给别人本来就是噪音。
   代价：导出跑到一半**刷新页面/换设备，那份结果没人接**（`clientId` 是每个页面现算的），再点一次即可。
2. **没带 `x-cherysis-client` 的客户端（curl 调试 / 很早以前的缓存页面）退回广播** ——
   宁可多发给别人，也不能让点了按钮的那台什么都收不到。
3. **只治了导出这一条**。`live.ts` 的九宫格/HTML/长图那三条**故意不动**：它们只在 VS Code 面板里跑
   （网页版跑的是手机版前端，那两个 tab 根本没入口），而 VS Code 那边只有一个面板，没有"别人"。

自查：`pnpm run check:server` 里有 3 组中枢用例（定向只给 target / 不跳过 origin / 不进缓冲）
+ 3 组收集器用例（在飞不推 / 脱钩定向 / 无 clientId 兜底）+ 4 条接线断言（handler → post → sinkPost
三段缺一段就静默失效），另用 8 条磁盘变异逐条确认它们真的会变红。

其他已知：删图偶尔失败多半是别的机器正占着那张图，等几秒重试即可
（第一张是封面，被读得最勤，最容易撞上）。
（表格**原先没有图片列**（看大图去画册）—— **2026-10-12 已补上**：**「名称」后面**一列缩略图
（填满行高、留一点缝、带圆角，行高没被撑高），没图的显示「无图」占位，
跟电脑端同一个思路。）

## 七、自检与排查

> ⚠️ **`pnpm test`（完整的 VS Code 测试套件）在开发这台机器上跑不起来**：
> VS Code 的扩展宿主拿不到可写的 `%TEMP%`，测试文件在加载阶段就 `EPERM: mkdtemp`，
> 早于任何被测代码执行 —— 是环境限制，不是测试或代码的问题（升权重试过一次，同样卡在这一步）。
> 所以本轮的替代证据是：`compile` + `lint` + 上面四条闸门（parity / server / mobile / longtask），
> 外加下面三个对着**真服务**跑的端到端脚本。要跑完整套件，请在能正常起 VS Code 的机器上
> `pnpm test`。

`/api/ping` 会把服务端的状态直接回给你，**出问题时先看它**（浏览器打开 `http://<IP>:端口/api/ping`）：

| 字段 | 怎么看 |
| --- | --- |
| `imageDirReady` | `false` = 图片根目录没配或不存在 → 看图相关的都会报错 |
| `tokenRequired` | `true` 时所有 `/api/*` 都要带 `?token=` |
| `eventClients` | 手机到底连上没有。`0` = 一个实时连接都没有 → 看手机端提示 |
| `rev` | 库的版本号（真改动才 +1）；`dataVersion` 是 SQLite 那边看到的"别人改过"计数 |
| `writeQueue` | 写队列深度。持续 >0 = 有写卡住了（多半是共享盘慢） |
| `tasks` | `running` / `waiting`：重活是不是在排队（「点了没反应」多半是这里） |

对着**测试库**跑的三个端到端脚本（会真的写测试库，所以默认拒绝指向正式库，除非 `--force`）：

```bash
# 先起测试服务（667 + tmp-web-test 三个路径）
node scripts/e2e-web-realtime.cjs     # 实时推送四件事：广播到旁观者 / 不重复打扰 / 巡检发现外部改动 / 并发写不丢
node scripts/e2e-web-fingerprint.cjs  # rev 的判据：真改动认得出、没改动不乱报
node scripts/e2e-web-tasks.cjs        # 长任务：请求立刻返回、queue 事件、进度推到手机、队列回空闲
```

常见现象对症：

| 现象 | 先看 |
| --- | --- |
| 手机打不开页面 | 服务在跑吗？同网段吗？防火墙？`/api/ping` 通不通 |
| 能打开但图片全是空白 | `imageDirReady`；图片根目录下是不是"每个商品一个子文件夹" |
| 别人改了这边不变 | 底部连接灯什么颜色？`eventClients` 是不是 0？对方那次改动是否有回推（没回推时会亮「有改动」而不是自动变） |
| 电脑版改了不提示 | `/api/ping` 的 `dataVersion` 有没有在变；不变说明服务端压根没看见外部改动 |
| 点了生成没反应 | `/api/ping` 的 `tasks`：在排队就等，`running` 空着还没动就是异常，看日志 |
