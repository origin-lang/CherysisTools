# shopTool 网页版方案 · 设计稿

> 状态：**设计定稿（2026-10-01）；M1 已落地，SSE 未做**；**手机版交互已实测定稿**（2026-10-02，见 §13）。
> 落地情况：`src/server/`（HTTP 宿主 + `/api/invoke` + `/api/image` + 静态托管 + 三级配置）与 `src/webview/mobile/`
> （手机版页面：画册/列表、详情、新建、就地改、筛选）都已可用；后端 handler 与数据库完全复用。
> **未落地**：SSE `/events`（见 §5）、`size=grid`（1024 排品图）、token 是否强制校验待确认。
> 关联：[http-中继方案-设计.md](http-中继方案-设计.md)（同一条接缝的另一条用法）、[shopTool.md](shopTool.md)、[shopTool-manual.md](shopTool-manual.md)、[局域网多机协作方案讨论.md](局域网多机协作方案讨论.md)
> 本稿目的：把"变成网页"这件事定在纸面上——做什么、怎么做、先做哪一步、哪些**明确不做**，免得将来凭记忆开工时走偏。

## 一、目标与约束（访谈定稿）

1. **首要目标：手机上也能用。** 不只是"不用装 VS Code"——手机要能翻商品、看画册、录当天销售。这一条决定了 M2 阶段（移动端适配）不能省。
2. **服务器就用现在那台主机**（放图片和数据库那台），不新增硬件。代价：主机关机/休眠时网页打不开。
3. **VS Code 版先并存**：网页版管日常（手机 + 客机浏览器），VS Code 版管重活（批量导图、九宫格、Excel 导入导出）。将来是否退役 VS Code 版，等网页版跑顺了再评估。
4. **本期只做局域网**。外网访问（内网穿透 / 云服务器）不做，但**鉴权要留位置**——手机连的 Wi-Fi 上往往不止你们几个人。
5. **尽量不加新东西**：HTTP 用 Node 内置 `http`（零新依赖，沿用本仓库设计稿的取舍），推送用 SSE 而不是 WebSocket，前端**先不引框架**、先不做打包/模块化。

### 明确不做（NO）

- 多店铺 / 多租户 / 账号体系与权限分级；
- 云部署、内网穿透、HTTPS 证书；
- 换成 Postgres/MySQL、重写数据层；
- 把 6 个 `client-*.js` 模块化 + 打包（另一笔账，会大幅抬高改动量，见 §10 风险）；
- 把 VS Code 版退役（将来单独评估）；
- 手机 App / 小程序。

## 二、为什么这条路便宜（架构事实，已逐条核对代码）

这个项目的前后端**本来就是靠一个消息接口分开的**，所以"换宿主"不需要动业务逻辑：

| 事实 | 位置 |
| --- | --- |
| 前端唯一出口：`post({ type, ... })` | `src/tools/shopTool/client-core.js`（`var post = (msg) => vs.postMessage({toolName:"shopTool", ...msg})`） |
| 前端唯一入口：`onMessage(msg)`，注册进 `window.toolClients.shopTool` | `src/tools/shopTool/client-main.js` 末尾 |
| 宿主壳负责：加载 fragment、注入 client 脚本、把收到的消息交给当前工具、日志区、Toast | `src/webview/main.html`（`loadToolClient` / `#logArea` / `showGlobalToast`） |
| 后端唯一入口：`handleMessage(msg, ctx)` | `src/tools/shopTool/index.ts` |
| 后端业务：**50 余个消息类型**（带 `msg` 参数的 49 个，另有 `loadAll`/`buildSharedThumbs` 这种不带参数的），按域拆在 6 个文件里 | `src/tools/shopTool/handlers/{settings,product,sales,image,settle,live,impexp}.ts` |
| 数据层 / 图像 / 合成：与宿主无关 | `db.ts`(better-sqlite3)、`images.ts`、`liveGrid.ts`、`pricing.ts`（sharp） |

**结论**：`index.ts` 的 `handleMessage` 加上 `db.ts` / `images.ts` / `liveGrid.ts` / `pricing.ts` / `productFields.ts` 这一整套，**一行都不用改**。要换的只有"宿主"那一层——就是 `ctx`（`ToolContext`）。

### 必须抽象掉的 VS Code 依赖（清单，已核对）

| 现在 | 位置 | 网页版怎么办 |
| --- | --- | --- |
| `ctx.panel.webview.postMessage`（回推） | `src/core/toolContext.ts` | `/invoke` 的返回值 + SSE |
| `ctx.log`（进日志区） | 同上 | 同上（收成 logs 数组 / SSE 事件） |
| `ctx.selectFolder / selectFile / selectFiles` | 同上（`showOpenDialog`） | **服务端配置路径**；导出改下载、恢复改上传（见 §6） |
| `ctx.confirm / chooseAction`（模态框） | 同上（`showWarningMessage`） | 前端自绘模态框（`client-core.js` 里已有 `confirmBox`，可直接复用） |
| `ctx.prefs`（本机 globalState，17 个偏好键） | `LOCAL_PREF_KEYS`（`index.ts`） | 浏览器 `localStorage`（语义反而更贴切：本来就是"跟人走"） |
| `panel.webview.asWebviewUri`（看大图） | `handlers/image.ts:319` | `GET /image?...`（见 §4.3） |
| `executeCommand("revealFileInOS")` ×5 | `image.ts:690`、`impexp.ts:398`、`live.ts:380/509/526` | 下载成品，或给一个 `\\主机\...` 链接 |
| `executeCommand("Cherysis.setStorageDir")` | `handlers/settings.ts:63` | 服务端配置（网页上只读展示） |
| `workspace.getConfiguration`（图片根目录） | `imageDir.ts:25/42/87/94` | 服务端配置 |
| `ToolRegistry`（建面板、`resourceRoots`、注入脚本） | `src/core/toolRegistry.ts` | 静态资源 + `initToolList` JSON（约 150 行的等价物） |
| `live_out_dir`（九宫格输出目录，"本机路径"概念） | `index.ts` / `handlers/live.ts` | 改成**服务端路径**，网页上只读展示 |

> 注意两个 handler 文件里直接 `import * as vscode`（`image.ts`、`live.ts`、`impexp.ts`、`settings.ts`、`imageDir.ts`）——**这一步要把这些调用也收进 HostAdapter**，否则 HTTP 宿主一 import 就崩。

## 三、部署形态

```
主机（放图片 + 数据库那台，常开）
├── cherysis-server（新 Node 进程，监听 0.0.0.0:13800）
│    ├── POST /invoke        → 复用现有 handleMessage（唯一写库入口）
│    ├── GET  /events        → SSE：日志 / 进度 / 后端的主动回推
│    ├── GET  /image?...     → 图片（thumb / grid / full 三档，带 ETag）
│    └── 静态托管 main.html + 各工具 fragment + client-*.js
└── VS Code 版（保留：批量导图、九宫格、Excel 这些重活）
     手机 / 客机浏览器 ──HTTP──→ http://<主机IP>:13800
```

- **端口 13800**：沿用 [http-中继方案-设计.md](http-中继方案-设计.md) 里定的端口，两套方案将来可以合并（那份是"客机的消息转发给主机"，这份是"整个界面搬到浏览器"，接缝是同一个 `handleMessage`）。
- **服务端配置**（不再依赖 VS Code 设置）：`storageDir`、`imageDir`、`liveOutDir`、`port`、`token`。来源优先级：命令行参数 > 环境变量 > `cherysis-server.config.json`（服务目录内）。
- **强烈建议**：主机上把 `imageDir`/`storageDir` 配成**主机本机路径**（如 `D:\商品图片`、`D:\shopData`），而不是 `Z:\`（回环 SMB）。少一层网络栈，看图和缩图都会明显快——现在主机自己也是走 `Z:\` 回环，白白多绕一圈。
- **开机自启**：Windows 任务计划（触发器=登录时）最省事；要"没人登录也跑"就用 nssm 注册成服务（代价：跑在 Session 0，`revealFileInOS` 这类桌面交互不可用——反正网页版本来也不用它）。
- **防火墙**：放行 13800（专用网络）。手机用 `http://<主机IP>:13800` 访问；可选带 `?token=...`。

## 四、接口设计

### 4.1 `POST /invoke`

```
请求：{ "type": "saveSale", ...payload }     ← 与现在 postMessage 的消息体完全一致，前端消息不改造
响应：{ "ok": true, "posts": [ ... ], "logs": [ "📝已记录 L001 卖5退0" ] }
```

- `posts` = 本次处理期间 `ctx.postToWebview` 发出的全部消息（按序），前端拿到后**照现在 onMessage 的分支逐条喂回去**——这样前端 `onMessage` 一个字都不用改。
- `logs` = 本次 `ctx.log` 的文本，前端自己插进日志区（现在日志区是后端的"写操作"，收成返回值更干净，也顺带解决"这条日志是谁触发的"）。
- **长任务不阻塞请求**：`buildSharedThumbs`（生成共享缩略图）、批量九宫格生成这类 handler 现在就是"后台跑 + 日志报进度"，`/invoke` 立刻返回，进度走 SSE。
- 只读/权限：本期不做账号；沿用 `readOnly` 的语义可以去掉（唯一写者），或改成服务端配置项。

### 4.2 `GET /events`（SSE）

事件：`log`、`toast`、`post`（后端的主动回推，如 `productsLoaded`/`coverLoaded`/`liveState`/`productsDelta`）、`progress`。

- 带 `id:` 与 `Last-Event-ID` 支持断线续传；心跳注释行（`:ping`）防中间设备掐连接。
- **为什么 SSE 不用 WebSocket**：只有服务端→客户端一个方向，单向够用；Node 内置 http 就能写，浏览器和手机上支持都好，调试只看一个 `curl`。

### 4.3 图片：`GET /image?code=L001&name=L001_2026.jpg&size=thumb`

- `size` 三档：`thumb`（512 封面，走现有两级缩略图缓存）、`grid`（1024 排品图，将来接九宫格提速）、`full`（原图，灯箱用）。
- 带 `ETag` + `Last-Modified` + `Cache-Control: private, max-age=...` → **手机第二次打开直接命中浏览器缓存**，这是现在 base64 方案做不到的。
- 为什么值得换掉 base64：现在封面/大图都是 base64 过 `postMessage`，每次全量传、webview 内存里还留一份字符串；HTTP 可以流式、可缓存、可 Range、可并发。
- 权限：图片端点同样走 token（不然整个商品图库就是公开的）。

### 4.4 静态资源与鉴权

- 静态托管 `src/webview/main.html` + 各工具 `fragment.html` + `client-*.js`（服务端按需拼 `initToolList`，等价于现在 `toolRegistry` 干的活）。
- 鉴权本期就是**一个共享口令**（`Authorization: Bearer <token>` 或 `?token=`，cookie 都不用）；**留位置**给将来的账号体系。不暴露到公网。

## 五、HostAdapter：整个方案成败的一层

目标：**handler 只认 `h.*`，不认宿主**。接口按现在 `ctx` 的实际用法逐条对齐：

```ts
interface HostAdapter {
  post(msg: unknown): void;                       // 回推（HTTP: 收进 posts / 或走 SSE）
  log(text: string): void;
  selectFolder(title?: string): Promise<string | undefined>;   // 网页版：不弹框，返回 undefined + 提示
  selectFile(filters?: Record<string, string[]>): Promise<string | undefined>;
  selectFiles(filters?: Record<string, string[]>): Promise<string[]>;
  confirm(title: string, detail?: string): Promise<boolean>;
  chooseAction(title: string, detail: string, actions: string[]): Promise<string | undefined>;
  prefs: { get<T>(k: string, def: T): T; update(k: string, v: unknown): Promise<void> };
  imageUrl(code: string, name: string | null, size: "thumb" | "grid" | "full"): string;
  revealInOS(path: string): Promise<void>;        // VS Code: revealFileInOS；HTTP: 交给前端下载/给链接
  readonly storageDir: string;
  readonly defaultStorageDir: string;             // HTTP 宿主里与 storageDir 相同
  readonly liveOutDir: string;                    // 网页版是服务端路径
}
```

- 两个实现：`VscodeHost`（把现有 `toolContext.ts` 包一层，**行为与现在完全一致**）、`HttpHost`（新）。
- `handlers/*.ts` 里那 5 处 `vscode.commands.executeCommand` 与 1 处 `asWebviewUri`、以及 `imageDir.ts` 的 `getConfiguration` 全部改走 `h.*`，并**在测试里禁止 handler 直接 import vscode**（一条 grep 断言即可，防止将来又漏回来）。
- 验收判据：`grep -r "from \"vscode\"" src/tools/shopTool/handlers/` 为空。

## 六、浏览器代替不了的 5 件事（本期的改法）

1. **选目录**（图片根目录、导出目录、从备份恢复选文件）——浏览器出于安全**不可能**列出服务器上的文件夹。→ 服务端配置（图片根目录、存储目录、输出目录）；**导出**改成浏览器下载；**从备份恢复**改成"上传一个 .db 文件"。
2. **打开文件夹**（`revealFileInOS` ×5）→ 改成"下载这张图/这个文件"；共享盘上的成品可以给一个 `\\主机\...` 链接（Windows 上可点开）。
3. **本机偏好**（17 个键：行高、字号、画册大小、字段显隐、导入导出勾选、九宫格输出目录、星标排版…）→ `localStorage`。语义上本来就更对（"跟人走、不写共享库"），而且换浏览器就换一份，符合直觉。
4. **大图 URI** → `/image?...&size=full`（顺带解决现在"base64 兜底"那条路）。
5. **`live_out_dir`（九宫格输出目录）**：现在是"本机路径"，网页版只能是**服务端路径** → 配置项，网页上只读展示，生成完给下载。

## 八、并存期怎么处理（VS Code 版 + 网页版）

1. **分工**：网页版当日常入口（手机 + 客机浏览器，看/录/排品预览）；VS Code 版只在主机上做重活（批量导图、九宫格、Excel）。
2. **同一个 `shop.db`**：现在是"跨 SMB 多机写"，搬网页后变成"同一台机器上两个进程写同一个文件"——**本机文件锁是可靠的**，比现在稳。已有的 `busy_timeout=10s` + `withRetry` 继续兜底。
3. 备份：两边都会跑"每日自动备份 + 操作前备份" → 各存一份（无害，占点磁盘）。
4. **撤销/重做**：它是整库快照回写。网页版里"别人改过"的直觉更弱（多人同时开着页面），建议 M1 先在网页版**隐藏撤销/重做**，或保留 `data_version` 冲突确认框，M2 再做"别人改过，点刷新"的提示。
5. **`🔒 只读`开关**在网页版没有意义（服务端是唯一写者）→ 不搬。
6. **共享缩略图**：网页版的浏览同样会走 `thumbToCachedBase64` 的读穿缓存 → 客机/手机第一次看图也会顺手把共享缓存填起来（那台机器锁了只读就不写，与现在一致）。

## 九、阶段计划与验收

### M1 · 能用（后端抽层 + HTTP 服务 + 界面原样搬过去）

做：`HostAdapter` 接口 + `VscodeHost` 包一层（**先保证 VS Code 版零回归**）+ `HttpHost` + `/invoke` + `/events` + 静态托管 + `/image` + `localStorage` 偏好 + 服务端配置与启动脚本。

验收：
- `pnpm run compile` / `lint` / 测试全绿，**VS Code 版功能一条不回归**；
- `grep from "vscode"` 在 `handlers/` 下为空；
- 手机浏览器打开 `http://<主机IP>:13800` → 能翻商品列表/画册、图片能显示（走 `/image`，不是 base64）、能录当天销售、月报能看；
- 服务重启后配置不丢（配置文件）；日志区与 Toast 正常。

### M2 · 手机顺手

做：§7 那张清单（1~9 条）+ "别人改过"的刷新提示 + 生成任务的服务端排队（同一时刻只跑一个生成任务，避免多人同时生成把 CPU/共享盘打满）。

验收：**单手**能完成三件事——录一笔销售、看某个商品的全部图、排一组九宫格并生成。

### M3 · 体验

做：拍照上传、PWA 可安装、画册卡片尺寸随屏幕自适应、离线缓存静态资源。

验收：手机拍照 → 该商品封面自动变；桌面图标打开即用。

## 十、风险与对策

| 风险 | 对策 |
| --- | --- |
| 手机连不上（防火墙/网段/IP 变了） | 先访问 `http://<IP>:13800/ping` 定位；文档里给一份排查清单（防火墙、专用网络、主机 IP、手机与主机是否同网段） |
| 主机休眠/关机 → 网页打不开 | 电源计划设"从不休眠"；服务开机自启；页面顶部显示"服务已断开，正在重连"（SSE 掉线即知） |
| **多人同时改同一个商品**（网页版是多人并发，VS Code 版没有这个问题） | 后端写入口本来就是"当下重新查库"（`getProductById`/`getProductByCode`），查不到会明确报错；M2 加"别人改过"提示；关键写操作保留前置备份 |
| 手机流量/带宽（大图、画册） | 列表只用 `size=thumb`；灯箱按需 `size=full`；ETag + `Cache-Control` 让第二次走缓存 |
| 局域网里也有别人（不是只有你们） | token；不暴露公网；图片端点同样要 token |
| 前端 6 个 `client-*.js` 共享全局作用域，在浏览器里会污染 `window` | 本期接受（与现在 webview 内一致，`window.toolClients` 本来就是全局约定）；要模块化就单独排期，别和搬宿主一起做 |
| `sharp` 并发（`IMG_READ_CONCURRENCY`、`BUILD_SHARED_CONCURRENCY`）在服务端会被多人叠加 | M2 加服务端任务队列（同一时刻一个生成任务），其余请求排队并回"正在生成中" |
| 网页版没有"打开文件夹"这类本机能力，用户会困惑 | 每个动作完成后把"文件在哪、怎么拿到"写在结果里（下载链接 / 共享路径），而不是静默 |
| 将来想把 VS Code 版也接到服务端（真·唯一写者） | 本方案的 HostAdapter 就是为它铺路：VS Code 版换成 `HttpHost` 即可变成纯客户端（与 [http-中继方案-设计.md](http-中继方案-设计.md) 合流） |

## 十二·补、手机版交互定论（2026-10-02 真机实测后定稿）

这一节是**"已经拍板的东西"**，不是待办。每一条都带理由 —— 后面有人想改，先看当初为什么这么定，
别把一个踩过的坑重新踩一遍。总原则：**手机是"手边干活"的设备，误触成本 > 多一拍的成本**。

| # | 定论 | 理由 / 踩过的坑 |
| --- | --- | --- |
| 1 | 表格里改值**两拍**：点一下选中那一格（绿色框），再点一下才弹底部 sheet | 弹 sheet 会顶出键盘，误触一下键盘就跳出来。选中态按 `{商品id, 字段}` 记，整行重画后框会补回去 |
| 2 | **状态列例外**：点一下直接切上/下架 | 二选一、没有输入框、不会顶键盘，误触再点一下就换回来，为它多加一拍不划算 |
| 3 | 进详情三个入口：点**编号**、sheet 里的「详情 ›」、**画册点卡片**；**双击进详情已删除** | 双击和"两拍改值"彻底冲突，曾经时灵时不灵 —— 那比没有更糟 |
| 4 | 所有输入框/下拉 **font-size ≥ 16px** | iOS 聚焦小于 16px 的输入框会把**整页**放大。全局硬规则，谁要改小先想清楚 |
| 5 | 操作结果走**屏幕下方提示浮层**（2.8s 自动消失）；日志收进底部细条左侧的「日志」按钮 | 用户要的是"成了还是没成"，不是日志。底部条整条不再可点（会挡翻页），按钮靠左（右下角是拇指区） |
| 6 | **只有列表表格有缩放**（`--zoom` 档位：筛选区 A−/100%/A＋ + 表格上双指捏合）；画册固定最小档（`GALLERY_ZOOM`）；**商品详情 / 新建 / 设置 / 大图都不给缩放** | 浏览器自带的是**整页**缩放，会把顶栏、筛选、分页条一起缩小 —— 那不是要的效果 |
| 7 | **整站禁掉浏览器的双指缩放和双击放大** | Chrome/安卓的捏合是合成器干的，JS `preventDefault` 拦不住，**只吃 CSS 的 `touch-action`**；iOS Safari 反过来不吃 `touch-action`，只能拦 `gesturestart/change/end`（挂在 document 上）；双击走另一条路，靠 `touchend` 判"320ms 内且落点移动 <30px"。缺一边就会漏掉一类浏览器 |
| 8 | 间距：`--pad:12`（屏幕左右留白）、`--gap:10`（相邻元素）、表单卡片 `padding:14`；**列表页按钮统一 44px** | 之前 `.card` 没有内边距（只有画册卡片的 `.body` 有），输入框直接顶到卡片边框 —— "黏着"的根因。按钮曾经 36/38/44 三种高度混在一排 |
| 9 | 顶栏 / 详情页「上一个 下一个」**不跟着滚** | 根因是 flex 经典坑：`.content` 是 `flex:1` 但没写 `min-height:0`，内容一高把 `100dvh` 撑破，滚动条落到**整个页面**上。写了 0 才是"这块自己滚、上面不动" |
| 10 | 新建页**等级默认「自定义」**（售价手填，不被规则重算） | 曾改成默认第一个真实等级，实际用下来：新建时多数已经知道卖多少，按规则算反而每次要确认"算出来的对不对"。要用规则定价时自己选等级，下面那行会显示公式 |
| 11 | 新建页**拍照后本地预览**：点小图看大效果、✕ 删、灯箱里「🔄 重拍」；保存后自动上传 | 图片挂在编号目录下，没编号传不了 —— 但**预览根本不需要上传**。之前只能等传完去详情页才发现拍糊了 |
| 12 | 表格**不加图片列**；看图去画册 | 图不在数据库里，只能现读共享盘：翻一页 50 行 = 50 个请求，首次还要现场缩图。想看"有没有图"用筛选区已有的 `imgStats` |
| 13 | 画册卡片：**第一行「进 ¥x → ¥y」，第二行库存** | 盘货/定价要一眼看到进多少卖多少；进价压成灰色，不跟售价抢视线；低库存仍标红 |
| 14 | 删图走 `unlinkForDelete`：先等后台缩略图 8 秒，失败再等 3 秒重试一轮 | **第一张（封面）总是删不掉**的病根：它是本进程读得最勤的那张，libvips 句柄没回收就 unlink 撞 EBUSY。原来统一只等 3 秒，而共享盘上生成一张缩略图就要 1~3 秒 |
| 15 | 列表页顶部的操作说明**已删** | 交互定型后那就是噪音，还占两行高度 |

### 改前端要知道的

- 前端三件套（`src/webview/mobile/`）是**静态直出 + `no-cache`**：改完刷新即可，**不需要编译**；
  后端 TS 改完必须 `pnpm run compile`（跑的是 `out/`）。
- 改 `app.js` 后顺手跑一次 DOM id 校验：把 `app.js` 里 `$("xxx")` 的 id 和 `index.html` 里的
  `id="xxx"` 对一遍（`codeQ` / `fsInput` 是 JS 动态生成的，不算缺失）。
- 编号语法在手机页和 `client-product.js` 里**物理上有两份**，`scripts/check-shopTool-parity.cjs`
  会逐字比对（13 条用例），不一致就报错 —— 这是防口径漂移的闸门，别绕过。
