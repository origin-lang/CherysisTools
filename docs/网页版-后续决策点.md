## 二、还没解决的 bug（都已有明确修法）

1. **导出带图仍然要几十秒** ✗
   实测：330 个商品夹，平均 **3.48 MB/张**、最大 **15.38 MB**（PNG）。
   - 读 50 张原图跨网络 ≈ **18 秒**（省不掉）
   - 解码这些大 PNG ≈ **几十秒**
   根治三条路（按性价比）：
   - ① 导出**不勾图片** → **秒级** ✓（已验证）
   - ② **图片目录搬到本机盘** → 省掉 18 秒的跨网络读图
   - ③ **把仓库里的 15MB PNG 换成 JPEG** → 读和解码都省（最狠）

2. **中继下"删除/清空"这类确认会被静默取消** ✗
   （服务端没有界面，`confirm` 只能返回"取消"）
   → 修法：把"需要确认 / 需要选择"的步骤**退回给发起方**（面板弹框 → 带答案重发）

3. **中继下取封面偶发 `ECONNRESET`** ✗
   （服务端空闲 5 秒会关连接，而 undici 不会像 `http` 那样自动重试）
   → 修法：服务端 `keepAliveTimeout` **5 秒 → 5 分钟**（`headersTimeout` 跟着调到 5 分 5 秒）
     ＋ **只读请求**（取封面这类）失败**自动重试 1 次**；**写操作一次都不重试**（怕重复写）

4. **服务端输出目录里散在根目录的文件**不会被"按天清理"碰到
   → 需要时加一个「清空输出目录」入口（网页版「设置 → 服务」那张卡片里最顺手）

## 五、丙方案：只移植"轮询自动刷新"（不动中继、不动版本号）

**背景**：现在这版（112009e = 0.0.19）**没有自动刷新** ✗ —— 它是 0.0.20 才加的，
而且和中继在**同一批提交**里 ✗。`git cherry-pick dc2d889` 没用（它改的是还不存在的代码，
而且它夹带了版本号/CHANGELOG/中继弹窗 ✗）。

**代码原文已从 `备份-中继与导出改动` 取出**，照下面做即可（约 10 分钟）：

### 1) `src/tools/shopTool/db.ts`
接口里加一行：`dataVersion(): number;`
实现里加：
```ts
dataVersion(): number {
  // 必须用主连接读：PRAGMA data_version 的语义是「别的连接提交过就变」，
  // 自己通过这条连接写的不会让它变。
  return Number(c.pragma("data_version", { simple: true }));
},
```

### 2) `src/tools/shopTool/index.ts`
文件级加：`let watchTimer: NodeJS.Timeout | undefined;` 和 `let watchLastDv = -1;`
加这个函数：
```ts
export function watchExternalChanges(
  storageDir: string,
  seconds: number,
  onChange: () => void,
): () => void {
  const period = Math.max(1, Math.floor(seconds)) * 1000;
  watchLastDv = -1;
  const tick = (): void => {
    let dv = -1;
    try {
      initDB(storageDir);
      dv = getDB().dataVersion();
    } catch {
      return; // 库没就绪/读不到：这轮跳过，别打扰用户
    }
    if (watchLastDv < 0) {
      watchLastDv = dv; // 第一枪只取基准：面板打开之前的改动不算"新变化"
      return;
    }
    if (dv !== watchLastDv) {
      watchLastDv = dv;
      onChange();
    }
  };
  tick();
  watchTimer = setInterval(tick, period);
  return () => {
    if (watchTimer) {
      clearInterval(watchTimer);
      watchTimer = undefined;
    }
  };
}
```
`shopTool` 定义里加字段 `watchExternalChanges,`（并在工具类型里加可选声明）。

### 3) `src/core/toolRegistry.ts`
- 加字段 `private stopChangeWatch?: () => void;`
- 面板打开/切换工具后：读 `cherysis.autoRefreshSeconds`（默认 **3**）；
  `<= 0` → 打日志 `ℹ️自动刷新已关闭（cherysis.autoRefreshSeconds = 0）…` 并返回；
  否则调 `meta.watchExternalChanges(storageDir, seconds, () => panel.webview.postMessage({ type: "externalChanged" }))`
  并打日志 `👀自动刷新已开启：每 N 秒检查一次「别人有没有改库」`
- 面板 dispose 时：`this.stopChangeWatch?.(); this.stopChangeWatch = undefined;`

### 4) `src/tools/shopTool/client-main.js`
- 加 `var externalRefreshPending = false; var externalRefreshWaiting = false;`
- 加 `isTypingText()`：**只认文本类 input / textarea / contenteditable**
  ⚠️ **千万别把 `<select>` 算进去** ✗ —— 这个仓库里焦点会一直赖在下拉框上，
  算进去就等于"自动刷新被永久按住"（这正是 0.0.21 修的那个真 bug）
- 加 `runExternalRefresh()`：正在打字 → 延后 + 弹一句提示；否则
  `toast("🔄 别人改了数据，已自动刷新")` + `post({ type: "loadAll" })`
- 消息分发里加：`case "externalChanged": externalRefreshPending = true; runExternalRefresh(); break;`

### 验收
1. 面板日志出现 `👀自动刷新已开启：每 3 秒检查一次「别人有没有改库」` ✓
2. 浏览器里改一条 → **3 秒内面板自己刷新** ✓（**焦点停在下拉框上也照样刷** ✓）
3. 在输入框里打字时 → 延后刷新并弹提示 ✓（不是静默等待 ✗）
