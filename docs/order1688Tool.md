## v0.1 已敲定的决策

- **输入源 = 剪贴板粘贴文本**：用户在 1688 订单详情页框选单个订单的表格区域 `Ctrl+C`，回到插件文本区 `Ctrl+V`。一个输入区可连续粘多个订单，订单之间用一行纯分隔线（`---` 或 `===`）隔开，逐条解析入库。**本期不做**浏览器驱动抓页/截图 OCR（对应原 skill 的 `grab_page.ps1` 路线），插件侧无法接管本机浏览器。
- **存储 = SQLite 主库（`order1688.db`）**：`orders`（订单头）+ `order_items`（商品明细）两张表，遵循插件管理类模块惯例（同 shopTool/procurementTool）。不用「只写 Excel」的方案——Excel 会被 WPS/Excel 打开锁定（Python 版反复踩坑），且不方便查询/筛选/去重。
- **去重 = 按订单号整单跳过**：`orders.order_no` 唯一，库中已存在该订单号则整单跳过并记日志，行为与 Python 版一致。v0.1 不做「覆盖/更新」选项。
- **回车/按钮触发解析**：文本区粘贴文本后**按 Enter 或点「🔍 解析文本」才触发解析**（粘贴本身不自动解析，避免输入法/多段粘贴反复触发），解析结果立即以表格形式呈现在下方预览区；明细表格带**首列复选框 + 表头全选/取消全选**，勾选行可「🗑 删除选中」整行删除，**每个单元格可编辑修改**；订单级也可整单丢弃不入库。用户核对无误后点「入库」才写库（对比 Python 版的直接写是唯一交互增强，避免把解析错误的脏行写进去）。
- **解析规则逐条移植自 `paste2order.py`**（字段缺失不编造，留空展示 `-`）：
  - 供应商：以 `供应商` / `卖家` / `供应商名称` 开头且带冒号（`：`或`:`）的行，去 `诚信通会员` 后缀；
  - 订单号：`订单号` / `订单编号` / `丁単号` / `丁里号` 开头的冒号后内容；
  - 下单时间：订单详情文本通常没有，留空 `-` 属正常；
  - 实付款：含 `实付款` 的行（可能无冒号，形如 `实付款 ¥ 160.50`），去 `¥/￥/,` 后取数字；
  - 商品区：以 `货品状态` 表头行为起点（缺省退回 `货品` 行）；每个 `货号:` / `丁里号:` 行往前两行 = 品名、规格；品名跳过 `7天/退货包运费/极速退款/48小时…` 等服务词与纯数字行；规格取含 `颜色`/`尺码` 的行并 `；` 合并；单价优先 `优惠后X元/件` 其次 `X元/件`；数量取货号后独立数字行（常为 `1`）；状态取 `退款成功/已确认收货/交易成功/已发货/待发货`。
- **导出采集表 = Excel（格式与 Python 版完全一致）**：列 `采集日期/订单号/下单时间/供应商名称/货号/货品名称/规格/数量/单价(元)/本订单实付款(元)`；同订单多行的「本订单实付款」列**合并单元格**只显示一个金额；**导出目录每次由用户选**（文件夹选择对话框），**文件名固定为 `1688采集信息表<YYYYMMDD_HHmm>.xlsx`**（如 `1688采集信息表20260906_1718.xlsx`，时间点=导出时刻）；用插件已有 `xlsx` 依赖（`!merges`）实现合并。
- **消息协议走 `toolRegistry`**，`ctx.log` 输出结果日志（成功/跳过/失败，多行列出问题行），和其余工具同一套壳。

## 一句话

把「1688 订单详情页框选 → Ctrl+C」的文本，粘贴进面板 → 自动解析成结构化订单（订单号/供应商/商品明细）→ 核对后入库 `order1688.db`，按订单号去重，可随时导出成与现有 Excel 采集表同格式的文件。

## 数据模型（db.ts）

- `orders`（订单头）
  - `order_no` TEXT 唯一 —— 1688 订单号；`collect_date`（采集日期 YYYY-MM-DD）
  - `order_time`（下单时间，通常空）、`supplier`（供应商名称）、`pay_amount`（本订单实付款，REAL）
  - `created_at`
- `order_items`（商品明细）
  - `order_id` INTEGER FK → orders.id；`huohao`（货号）、`name`（货品名称）、`spec`（规格，颜色/尺码 `；` 合并）、`qty`（数量）、`price`（单价）
关系：1 订单头 ∶ N 商品明细行，`order_items` 按 `order_id` 查明细，明细在导出时逐行进表。

## 页面（2 个 Tab）

1. **抓取入库**：文本区粘贴 1688 订单文本（多个订单用 `---`/`===` 分隔）→ **按回车或点「🔍 解析文本」触发解析** → 下方预览区立即显示「订单摘要 + 商品明细表」（明细表首列复选框 + 表头全选/取消全选 + 「🗑 删除选中行」 + 单元格行内编辑）→ 核对后「✅ 入库」写库；连续粘下一单接着入库。入库后日志区报告 `✅成功 / ⏭跳过(已存在) / ❌失败(未解析到订单)`。
2. **订单记录**：按日期/供应商/订单号筛选的订单+明细列表（明细可折叠展开），支持删除选中、右键复制（沿用 procurementTool 的 TSV 复制能力）、「导出采集表 Excel」——**点按钮弹文件夹选择框选导出目录**，文件名自动生成 `1688采集信息表<YYYYMMDD_HHmm>.xlsx`。

## 关键流程

- **抓单入库**：粘贴后按 Enter / 点「🔍 解析文本」触发 → `clean_lines` → 按 `---/===` 切成块，每块 `parse_order` → 无订单号/无明细则 `❌` 记日志（该项不进预览）→ 有则回传预览表 → 用户核对/改格/删行后「入库」→ `db.add`：订单号已存在整单跳过（`⏭`），否则写 `orders` + 明细 → 日志报告 + 刷新记录列表。结束这批后到「订单记录」按上面流程导出。
- **导出采集表**：用户点「导出」→ 弹文件夹选择框（`ctx.selectFolder`）→ 取 `orders ⋈ order_items` 按 10 列拼行（导出全部记录）→ 写 `1688采集信息表<导出时刻YYYYMMDD_HHmm>.xlsx` → 同订单连续多行合并「本订单实付款」单元格 → 日志给完整文件路径；文件被占用（Excel/WPS 打开）时报错并提示关闭重试。

## 使用注意

- **编译分隔（重要）**：`index.ts` / `db.ts` 改动需 `pnpm run compile`；`fragment.html` / `client.js` 由后端运行期直接读 `src/`，改完 F5 重载扩展或切走再切回即生效。
- **解析依赖页面文本格式**：1688 页面改版可能导致解析失败，症状是日志大量 `❌未解析到订单`，此时把原样文本贴进「解析」后截图反馈即可对照调正则。
- **Excel 导出被占用**：WPS/Excel 打开目标文件会导致写入失败，日志会提示关闭后重试（与 Python 版同一限制）。
- **去重口径**：以订单号为准、整单跳过，删库/清记录后再次导入会重建记录。
