## 一、多机共享 + 只读模式（**必须两台机器 / 两个账号**，单机测不出来）

前置：两台机器指向**同一份** `shop.db`。约定「**一台写、另一台只读看**」—— 共享盘是 SMB/SQLite，
多机同写会互抢排他锁，写事务在网络上失败就是 `❌操作失败：disk I/O error`。

- [ ] **1.1** B 点 `🔓 可写` → 确认框 → 变 `🔒 只读`（红底），撤销/重做/新建变灰

## 二、商品图片删除（真实 `EBUSY` 只能在真机 + 共享盘复现）

`EBUSY` 取决于那一刻谁攥着句柄（杀软实时扫描、缩略图生成器、资源管理器、另一台机器的 SMB 会话），
**不可控也不可重入**，所以单测全部靠注入 `unlink` 伪造 —— 验的是重试序列与记账，**验不了
「Windows 真的把句柄放开了」**。

- [ ] **2.1** 图库抽屉右键某张 → `🗑️ 删除图片` → 抽屉**立刻关闭** → 列表里确实没了。
      （改之前这条 100% 失败：Chromium 攥着 webview URI 的句柄）
- [ ] **2.2** 删的时候看时间：不该再有那 4 秒的整库备份等待；备份目录**不该新出 `shop_pre_` 文件**
- [ ] **2.3** 同一编号多张时逐个删 → 每次都应成功
- [ ] **2.4** 「清空图片夹」→ 日志报「已清空 X 图片文件夹（N 张）」，**数字要真的等于删掉的数**；
      对空夹点 → 应说「本来就是空的」
- [ ] **2.5** ⚠ **占用者场景**：用照片查看器打开某张图**别关** → 回来删 → 重试 4 次后提示要看得懂
      （「文件正被占用。删图前请先关掉正在看的大图预览…」），而不是甩一个 `EBUSY`
- [ ] **2.6** 失败后列表/图库必须反映**磁盘真实情况**（图还在），别停在"已删掉了"的假状态
- [ ] **2.7** ⚠ 从**另一台机器**用资源管理器打开这张图 → 本机删 → 会失败并提示
      「如果是别的机器…也关掉再试」（SMB 协议限制，**重试救不了**）
- [ ] **2.8** ⚠ **回归重点**：跑一次「生成星标总览图」，**不重载窗口**，预览一出来就关弹窗、
      立刻删那批星标商品里任意一张原图 → **必须删得掉**（改之前会撞后台读图任务）
- [ ] **2.9** 上传/换封面之后**立刻**删同一张图 → 应成功（这是本轮最大收益）
- [ ] **2.10** 刚跑完「生成星标总览图」或导出之后立刻删图 → 应成功

## 六、电脑端筛选面板的「类型」「图片」两组（2026-10-11 新增，跟手机版对齐）

改的是 `client-product.js` / `client-main.js` / `client-core.js`（旧名 `fragment.html` 未动）。**不用编译**，
重载窗口（或切一下工具再切回来）即生效。前置：**图片根目录已经设好**，库里至少有「有图」和「无图」的商品各一个。

- [ ] **6.1「类型」组**：面板里多了一组**类型**（展开后是 `套装 N` / `普通 M` 两个复选框，带全选）；
      勾「套装」→ 列表只剩套装、筛选条上出现胶囊「**类型：套装**」；再勾「普通」→ 两类都出来
- [ ] **6.2 类型只认字段不认编号**：判定看的是商品的类型字段，不是编号前缀。
      正常路径上这两者一致（后端管着「T 开头必须是套装」），**人工基本造不出反例** ——
      所以这条主要靠自检里那条变异（把判定改成认 `T` 前缀就得变红）看着。
      人工能顺带验的是：**套装**那一件点开详情，右上角是「套」标记；「类型」勾「套装」之后它一定在里面
- [ ] **6.3「图片」组先显示统计中**：**第一次**打开筛选面板、展开「图片」→ 这一组写的是
      「**正在统计每个编号的图片数量…**」（不是「全选 (0) / 没有匹配的选项」那种空清单）
- [ ] **6.4 数完自动变**：等一两秒（不用管它）→ 那组**自己**变成 `无图 N` / `有图 M` 两个复选框，**不用重开面板**
- [ ] **6.5 筛「无图」**：勾「无图」→ 列表只剩**图片夹是空/不存在**的那些商品；筛选条上出现「**图片：无图**」；
      对照一下：随便点一个的封面 → 确实是「暂无图片」
- [ ] **6.6 传图之后计数跟着变**：给其中某一个「无图」商品**上传一张图** → 回到面板：它的「无图」计数 **-1**、
      「有图」**+1**（就地更新，不用等重扫）
- [ ] **6.7 传图后列表立刻重算**：**筛着「无图」**的时候给列表里某一件传一张图 → 它**当场从列表里消失**
      （因为已经不是「无图」了）；点筛选条上「图片：无图」的 `✕` 撤掉条件 → 它又回来、封面是新图。
      再把这张图删掉 → 筛「无图」它**重新出现**（两个方向都要看）
- [ ] **6.8 统计没回来时不误伤**（难复现，靠日志/断网模拟）：统计还没回来的时候这一列**按「不筛」处理**
      —— 绝不能出现「一开筛选就空表」。想稳妥复现：把图片根目录指向一个**很慢/断掉**的映射盘，
      打开面板立刻勾「无图」→ 列表应当是**全部商品**（不是空的），并留意日志
- [ ] **6.9 不白扫**：统计过一次之后，反复关/开筛选面板 → **不再重复统计**（日志里不会有第二遍扫描；
      慢盘上表现为第一次之后每次开面板都是秒开）
- [ ] **6.10 纯刷新不重扫**：统计完之后点顶栏 **🔄 刷新** → 再开面板，「图片」计数**仍是现成的**（不重新数）；
      但**新建一个商品**（或导入一行）之后再开面板 → 会重新统计一次（编号集合变了）
- [ ] **6.11 两组都能撤**：点筛选条上「类型：套装」「图片：无图」两条胶囊各自的 `✕` → 条件立刻撤、列表放开；
      「清除全部」也能把这两条一起清掉
- [ ] **6.12 不影响别的**：这两组**不写进**导出/复制列；「搜哪一列」下拉里**没有**类型/图片这两项（它们是面板专用的离散列）
