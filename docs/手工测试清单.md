## 一、多机共享 + 只读模式（**必须两台机器 / 两个账号**，单机测不出来）

前置：两台机器指向**同一份** `shop.db`。约定「**一台写、另一台只读看**」—— 共享盘是 SMB/SQLite，
多机同写会互抢排他锁，写事务在网络上失败就是 `❌操作失败：disk I/O error`。

- [ ] **1.1** B 点 `🔓 可写` → 确认框 → 变 `🔒 只读`（红底），撤销/重做/新建变灰
- [ ] **1.2** 关掉面板重开 → 仍是 `🔒 只读`（存 globalState，本机持久化）
- [ ] **1.3** 只读下改商品字段 / 新建 / 删商品 / 录销售 / 改名称模板 / 上传删图 / 点星标 → 全部拦下，**库里没变**
- [ ] **1.4** ⚠ **别误伤**：只读下 `🔄 刷新`、`📁 更换数据库目录`、导出、生成九宫格/星标总览 **都要能点**
- [ ] **1.5** 只读下调**字号 / 行高 / 字段显隐** → 能改、立刻生效、日志是 `⚙️设置已保存（只影响本机）`，**不报只读**
- [ ] **1.6** 只读下九宫格格子里敲编号、停手 2 秒 → 日志**干净**，没有一句 `🔒`

### 偏好本机化（不再互相覆盖）

- [ ] **1.7** A 把字号调 20、行高 10 → A 立刻变；A 点 `🔄 刷新` → **还是** 20/10
- [ ] **1.8** ⚠ B 点 `🔄 刷新` → B 的字号**没跟着变**（这是本轮的核心修复，必须确认 B 没变）
- [ ] **1.9** A 关掉几列「字段显示」→ B 刷新后**列不变**
- [ ] **1.10** 星标总览：A 选 4×3 并确定 → 再打开是 4×3；**B 的排版不受影响**；A 改标注 → 确定 → **再打开正确回填**
- [ ] **1.11** 两台机器**同一秒**给同一编号上传图 → **两张都在**（文件名带毫秒）

### 查库核对（最硬的证据）

- [ ] **1.12** 在共享盘那份 `shop.db` 上 `SELECT key, value FROM settings;`
      → 只剩 `name_template` / `stock_alert` / `sales_deduct_stock`（+ 历史遗留的 `image_dir`、`auto_backup_date`）。
      `font_size` / `row_height` / `col_*` / `live_out_dir` / `star_*` / `import_*` / `export_fields` **都不该再被更新**
- [ ] **1.13** A 改一次字号 → 重查库，确认 `font_size` **没变**
- [ ] **1.14** 只读端 B 改任何数据 → 查库确认**零变化**
- [ ] **1.15** 本机偏好确实落在 `%APPDATA%\Code\User\globalStorage\state.vscdb`；**共享盘上没有新增文件**

### 撤销保护（一人写时不该看到确认框）

- [ ] **1.16** A 连续改 3 次再撤销 → **不弹任何确认**（一个人写时 data_version 不变）
- [ ] **1.17** ⚠ **两人同时写才弹**：A 改一次 → B 解锁只读再改一次 → A 点撤销 → **必须弹确认框**
- [ ] **1.18** 上一步选取消 → **B 的改动还在**；再点一次选确定 → B 的改动被一起撤掉（预期）

### 手动刷新（替掉了自动同步）

- [ ] **1.19** B 面板一直开着、**不点 🔄** → A 改售价 → B 列表**不变**（自动同步确实删了）
- [ ] **1.20** B 点 `🔄` → 售价/累计售出/退款**一起**更新；新增商品、今日销售、改规则、删商品都能刷出来
- [ ] **1.21** ⚠ B 停在第 3 页时 A 改的不是当前页商品 → B 刷新后**仍停在第 3 页**
- [ ] **1.22** 静置 1 分钟什么都不做（两端）→ 日志区**不再周期性冒刷新**
- [ ] **1.23** B 停着面板、完全不点按钮 → 共享盘上 B 端**零写**（看 `shop.db-journal` 不出现）

### 封面 / 图片

- [ ] **1.24** B 停在有封面的商品上 → A 给其中一行换图 → B 点 `🔄` → **那一行封面变成新图**

## 二、商品图片删除（真实 `EBUSY` 只能在真机 + 共享盘复现）

`EBUSY` 取决于那一刻谁攥着句柄（杀软实时扫描、缩略图生成器、资源管理器、另一台机器的 SMB 会话），
**不可控也不可重入**，所以单测全部靠注入 `unlink` 伪造 —— 验的是重试序列与记账，**验不了
「Windows 真的把句柄放开了」**。

- [ ] **2.1** 图库抽屉右键某张 → `🗑️ 删除图片` → 抽屉**立刻关闭** → 列表里确实没了。
      （改之前这条 100% 失败：Chromium 攥着 webview URI 的句柄）
- [ ] **2.2** 删的时候看时间：不该再有那 4 秒的整库备份等待；备份目录**不该新出 `shop_pre_` 文件**
- [ ] **2.3** 同一编号多张时逐个删 → 每次都应成功
- [ ] **2.4** 「清空图片夹」→ 日志报「已清空 X 图片文件夹（N 张）」，**数字要真的等于删掉的数**；
      对空夹点 → 应说「本来就是空的」
- [ ] **2.5** ⚠ **占用者场景**：用照片查看器打开某张图**别关** → 回来删 → 重试 4 次后提示要看得懂
      （「文件正被占用。删图前请先关掉正在看的大图预览…」），而不是甩一个 `EBUSY`
- [ ] **2.6** 失败后列表/图库必须反映**磁盘真实情况**（图还在），别停在"已删掉了"的假状态
- [ ] **2.7** ⚠ 从**另一台机器**用资源管理器打开这张图 → 本机删 → 会失败并提示
      「如果是别的机器…也关掉再试」（SMB 协议限制，**重试救不了**）
- [ ] **2.8** ⚠ **回归重点**：跑一次「生成星标总览图」，**不重载窗口**，预览一出来就关弹窗、
      立刻删那批星标商品里任意一张原图 → **必须删得掉**（改之前会撞后台读图任务）
- [ ] **2.9** 上传/换封面之后**立刻**删同一张图 → 应成功（这是本轮最大收益）
- [ ] **2.10** 刚跑完「生成星标总览图」或导出之后立刻删图 → 应成功

## 三、手机网页版（**必须真手机 + 真中文输入法**）

后端回包快的时候（电脑浏览器、本机）复现不出来，手机上后端慢、输入法是中文，才撞得上。

- [ ] **3.1** 编号范围输 `A1~A33` → **能筛出东西**，不是「没有匹配的商品」
- [ ] **3.2** ⚠ **全角波浪号**：用中文输入法打 `347～348`（全角）→ **必须和半角 `347~348` 结果一样**。
      这是「电脑没问题、手机不行」的真凶
- [ ] **3.3** ⚠ **中文输入法**：名称框里用**拼音打一个词** → **不能出现「多出好多字」**；
      拼音输入中按空格**选词** → 正常上屏
- [ ] **3.4** 名称框直接按空格 → **打不进去**；**粘贴**带空格的文字 → 粘贴瞬间不改字，
      **离开这一格**才洗掉并提示「已去掉 N 个空格」
- [ ] **3.5** 备注框里打「客户说要改链条 18cm」→ 空格**能打进去**、失焦原样保存、重进详情还在
- [ ] **3.6** 备注框在 iPhone 上点进去 → **整页不会被放大**（iOS 对 <16px 输入框会自动放大整页）
- [ ] **3.7** 详情页右上角一个 **📷** → 弹出系统**「相机 / 照片图库」两项**（不是直接进相机）
- [ ] **3.8** 新建商品编号框**留空**点「用下一个空号」→ 给 `A001`（或 A 段下一个空号），**不是 `L001`**；
      先打 `B` 再点 → 给 B 段的空号
- [ ] **3.9** 展开筛选 → 在 进价/售价/库存 的「最小~最大」打字 → 等图片统计数完，**正在打的数字还在**
