# 打包发布（Cherysis vsix）

> 目的：以后打完包直接照这份做，不用再想"先干嘛、要不要抬版本、会不会漏文件"。
> 适用：**在这台开发机上出 vsix 发给别人**。

---

## 一、最短路径（三步）

```powershell
# 1) 抬版本号（package.json 的 version；CHANGELOG 顶部加一段同名小节）
#    例：0.0.29 → 0.0.30

# 2) 打包（会自动编译 + 跑 5 道自检 + 跑打包体检，任何一步红都会中止）
pnpm run package

# 3) 确认产物
Get-Item Cherysis-0.0.30.vsix
```

产物名就是 `Cherysis-<package.json 的 version>.vsix`，落在仓库根。

`pnpm run package` 实际是：

```
vsce-pnpm package            ← 真打包（它自己会触发 vscode:prepublish）
pnpm run check:package       ← 打包后体检真实清单（见第五节）
```

而 `vsce-pnpm package` 会先触发 `package.json` 里的 **`vscode:prepublish`**：

```
tsc -p ./                    编译 src → out
check:parity                 前后端字段/编号筛选口径无漂移
check:webserver              网页版服务工具接线
check:server                 服务端单元（EventHub/队列/长活儿）
check:mobile                 手机版 id 接线 + 筛选面板 + 空格拦截
check:longtask               长活儿 handler 语义
```

⚠️ **别用 `npx vsce package` 直接打** —— 它**不会**跑 `vscode:prepublish`，也就跳过了上面 6 道闸门，而且不处理 pnpm 的生产依赖收集（那步靠 `vsce-pnpm` + `patches/vsce-pnpm@0.1.0.patch`）。

## 二、抬版本号要动哪

| 文件 | 改什么 |
| --- | --- |
| `package.json` | `"version": "0.0.30"` |
| `CHANGELOG.md` | 把顶部的 `## [未发布]` 改成 `## [0.0.30] - <日期>`（这段本来就攒着本轮的改动） |

`package.json` 的 `name` / `publisher` 决定安装后的身份：`Faye.Cherysis`，**改这两个会让用户那边的数据目录变位置**（数据在 `globalStorage\Faye.Cherysis\`），所以别动。

## 三、发给别人之前，先知道包里有什么

**已经踩过两次坑，都写进闸门了：**

### 坑 1：前端静态资源缺一个 = 功能静默失效

这个扩展的前端是**静态直出**：`src/tools/*/fragment.html` 和 `src/tools/*/client*.js` 在运行时由 `toolRegistry.resolveSrc()` **直接从 `src/` 读**（不是打包进 bundle）。所以它们在 `src/` 里，也在 vsix 里 —— `.vscodeignore` 里 `src/**/*.ts` 会把 TS 排掉，但这些 `.html` / `.js` 不是 `.ts`，本来就进包。

**危险点**：谁要是顺手加一条 `src/**` 之类的排除，扩展装上去某工具就是"点了没反应"、**不报任何错**（`src/test/extension.test.ts` 里有一条断言专门盯"源码必须留在 src 下"，但盯不到 vsix 里有没有）。
→ 现在由 `check:package` 的"必需资源齐全"兜住。

### 坑 2：开发笔记与本机路径会一起发出去

vsce **默认把仓库根的所有文件**打进 vsix。所以仓库根的开发产物以前是**真的进了包**：

- `docs/**`（设计稿、归档、测试数据说明 —— 里面写着 `C:\Users\<用户名>\...`、`\\<NAS 名>\...` 这种真实路径）
- `scripts/**`（开发工具链：`check-*` / `seed-*` / `e2e-*`）
- `patches/**`、`out/test/**`（编译出来的测试）
- 那些 `*.vsix` 历史包

→ 现在全在 `.vscodeignore` 的排除列表里。**而且 `CHANGELOG.md` 与 `docs/order1688Tool.md` 里曾经有实名路径**（`C:\Users\YFF\...`），是 `check:package` 的内容扫描逼出来的，已改成 `<用户名>`。

## 四、`.vscodeignore` 的规矩（改之前先读这段）

现有排除项分三类，**改动原则：只加不减，减之前先确认没有运行时代码去读它**。

| 类别 | 条目 | 为什么 |
| --- | --- | --- |
| 开发/构建 | `.vscode/**` `.vscode-test/**` `**/tsconfig.json` `**/eslint.config.mjs` `**/*.map` `src/**/*.ts` `src/test/**` `out/test/**` `.pnpm-store/**` | 不是运行时需要的 |
| 本机私有 | `cherysis-server.config.json` `cherysis-server.config.demo.json` `tmp-web-test/**` `logs/**` `.workbuddy/**` `.agents/**` | 夹带本机真实路径/口令/演示库 |
| 发给别人别带 | `docs/**` `scripts/**` `patches/**` `测试清单-本轮改造.md` `*.vsix` | 内部笔记与开发工具，终端用户用不上 |

⚠️ **`scripts/**` 之后必须跟着三条例外**，否则装上就炸：

```
scripts/**
!scripts/serve-web.cjs
!scripts/stop-web.cjs
!scripts/autostart.ps1
```

这三个是**运行时**入口，不是开发工具：四个 `.cmd`（启动/停止/设自启/取消自启）和面板的「▶ 启动」按钮最终跑的都是 `node scripts/serve-web.cjs`。0.0.30 第一次打包把它们一并排掉了，表现是**装上点启动立刻报 `Cannot find module '...\scripts\serve-web.cjs'`**（那个路径是用户机器上的扩展目录）。`check-package` 的"必需资源齐全"现在盯着这三个和四个 `.cmd`，并且 `scripts/` 改成白名单制（只允许这三项）。

**留在包里的**（都是故意的）：`README.md`（用户手册）、`CHANGELOG.md`、`package.json`、`pnpm-lock.yaml` + `pnpm-workspace.yaml`（vsce-pnpm 解析依赖要用）、`images/**`（图标）、`cherysis-server.config.example.json`（给人抄的模板）、根目录四个 `.cmd`（启停服务/开机自启的入口）、`src/webview/main.html` + `src/webview/mobile/**`（壳与手机版页面）、`src/tools/**/fragment.html` + `client*.js`、`out/**`（编译产物）。

> ⚠️ 别写 `!src/webview/**/*` 这类反排除 —— 那会把 `src/webview/toolTree.ts` 这种**编译型** TS 又捞回来（它是 `import "./webview/toolTree.js"` 用的，源码进包只会误导）。

## 五、打包体检 `pnpm run check:package`

`scripts/check-package.cjs`，用 `vsce ls --no-dependencies` 拿**真实清单**再查四件事：

1. **必需资源齐全** —— `out/extension.js`、`src/webview/main.html`、`src/webview/mobile/{index.html,app.js,style.css}`、`shopTool` 的 `fragment.html` 与 6 个 `client-*.js`，以及**每个工具目录的 `fragment.html`**（工具列表来自注册表，缺一个那个工具就是空白）
2. **禁入项** —— 第三节那批，出现即失败
3. **内容扫描** —— 逐个文本文件找 `C:\Users\<真实用户名>\` 与 `\\<机器名>\<共享名>\`。占位符（`你的用户名` / `<某人>` / `%VAR%`）放行
4. **清单规模** —— 条目数/扫描数太少会报"这道闸门已失效"，**宁可红也不假绿**

红了就照提示改 `.vscodeignore`（或把实名路径改成占位符），别绕过。

## 六、平台与依赖（重要）

- **`sharp` 和 `better-sqlite3` 是原生模块**，编译产物跟**平台与 ABI** 绑死。在 Windows 上打的包**只能在 Windows 用**；要发 mac/Linux 得在对应平台各打一次。别把 Windows 包发给 mac 用户，会装不上或一用就崩。
- 扩展宿主是 VS Code 的 Electron，原生模块的 ABI 必须对得上 —— 所以**别手动往 `node_modules` 里塞别处拷来的 `.node` 文件**。
- `package.json` 的 `engines.vscode`（现在是 `^1.80.0`）是**最低版本**。用老于它的 VS Code 会直接装不上。
- 收包的人**不用装 pnpm**，双击 vsix 或 `code --install-extension Cherysis-0.0.30.vsix` 即可。

## 七、让别人装（发给别人的话照这条写）

1. VS Code → 扩展面板 → 右上 `⋯` → **从 VSIX 安装…** → 选 `Cherysis-0.0.30.vsix`
   （或命令行 `code --install-extension Cherysis-0.0.30.vsix`）
2. 装完**重启 VS Code**
3. 侧边栏出现 `Cherysis 小工具集`，或命令面板搜 `Cherysis: 打开工具面板`
4. 要多人共用一份数据：在「规则与设置」里设**数据库目录**指向共享盘；
   **商品图片根目录是每人各设一次**（命令面板 → `Cherysis:设置商品图片根目录`），因为它跟人走

> 手机版（网页版）是另一回事：它需要跑 `pnpm run serve` 那个 Node 服务，见 `docs/网页版-使用与运维.md`。**vsix 本身不含跑服务的能力**（服务代码在包里，但要手动启）。

## 八、常见问题

| 现象 | 原因 / 怎么办 |
| --- | --- |
| `pnpm run package` 在 `check:*` 就红了 | 先修那一道，别绕过 —— 它们是唯一能发现"前后端口径漂移 / 手机版 id 写错 / 长活儿语义变了"的地方 |
| 打包成功但装上某工具空白 | `check:package` 的"必需资源"应该已经拦住；真漏了就查那个工具的 `fragment.html` 是否被排除 |
| 别人装上后图片全不显示 | 八成是**图片根目录没配**（每人各设一次）。面板日志区会有一行说明 |
| 别人那边数据库是空的 | 数据目录没指向共享盘（默认落在各自 `%APPDATA%`），不是包的问题 |
| 想验证包内容但不想真打包 | `npx vsce ls --no-dependencies` 列清单；`pnpm run check:package` 直接体检 |
| 误报了内容扫描 | 确实是占位符就按 `scripts/check-package.cjs` 里 `LEAK` 的写法加豁免，**别整个关掉扫描** |
| 装上点启动报 `Cannot find module '...\scripts\serve-web.cjs'` | `.vscodeignore` 把 `scripts/` 排除时**没放行那三个运行时入口**（见第四节） |
| `pnpm run package` 比预期慢 | `check:package` 里的 `vsce ls` 会**再触发一次 `vscode:prepublish`**（编译 + 5 道检查全跑一遍）。慢是正常的，不是卡住 |
| 环境里 `pnpm install` 报 `[ERR_PNPM_EPERM] ... rename ...better-sqlite3...` | 受限环境（沙箱/权限管控）拦了 pnpm 的原子替换。**别中断它**——中断会导致 `node_modules` 整层链接被回滚清空，之后 `pnpm install` 还一直说 `Already up to date` 不肯重建。真踩了就换到有写权限的环境重装，或者按 `.vscodeignore` 那种"一层层补 junction"的方式救（Windows 上要用 `junction`，普通 symlink 需要管理员权限） |
